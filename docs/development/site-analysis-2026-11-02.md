## 登录 503 误报修复

浏览器出现 `/api/auth/login` 和 `/api/system/site-settings` 返回 503 时，原登录失败处理中间件会把所有 `success:false` 响应当作凭证错误，添加 `X-Login-Attempts-Remaining` 并累计失败次数，前端又优先读取该响应头，最终显示“用户名或密码错误”。

现已收口为统一状态规则：只有 HTTP 401 凭证失败才计数、写入 `invalid_credentials` 日志和返回剩余次数；账户禁用改为 403；500/502/503/504 会移除登录尝试响应头，不触发前端本地锁定。登录页按状态码优先显示“登录服务暂时不可用，请稍后重试”，不再把数据库故障伪装成密码错误。失败日志在数据库断开时先检查连接，避免产生二次数据库错误。

新增 `backend/test/login-attempts-contract.check.js`，覆盖 401 计数、重复响应防重复计数和 503 不计数三项行为；该契约已纳入后端全量测试。
