## 三、公共资料、分类与规格

### 分类的数据库来源

现有分类来源曾是 `accessories.category` 文本字段；代码和迁移脚本新增配件专用 `accessory_categories`、`accessory_units` 和适配型号关联表，并由 `/accessories/catalog` 独立维护。2026-11-12 已在用户授权下完成当前配置所连云端迁移，按旧文本精确初始化，不自动合并保护壳/手机壳、贴膜/钢化膜等名称，不改手机资料。商品模板以 `category_id`、`unit_id` 关联，停用分类保留历史引用；执行及原数据核验证据见[入库正文](../backend/accessory-entry.md)。

类型主档负责分类、名称、排序和启停用；单位独立维护，不在类型上控制是否用于贴膜或免费。模板仅以“免费专用”（`free_film`）控制是否参与免费自动匹配，移除“用于贴膜”；模板保留正常零售价。开关开或关均可收费，具备赠送权限时也可手动赠送。迁移对照现有分类值，明确“保护壳/手机壳”“贴膜/钢化膜”等是否同义后再映射，不自动猜测合并；按字段契约完成迁移及调用替换后只保留一个权威类型定义。停用类型不抹除历史名称，不再以页面硬编码选项充当主档。现有类型贴膜标记不能直接推定为该类型全部模板可免费，模板配置须显式核对。

| 资料 | 目标共享边界 |
| --- | --- |
| 门店 | 复用 `stores` 及现有门店服务 |
| 供应商 | 复用 `suppliers`，增加常规、配件多选业务范围 |
| 品牌、颜色 | 复用现有主档；品牌按手机/商品用途筛选，同品牌不重复建档 |
| 型号 | 区分商品自身型号和适配手机型号；适配机型引用手机型号并可多选，自身型号的存储范围在结构核验后确定 |
| 内存及其他规格 | 手机继续使用现有内存；商品沿用配件型号、颜色、单位及适配关系。用户已要求移除独立“配件规格”字段，不因任务描述“统一分类/规格”重新增加规格库或输入框；容量、功率等可按商品名称/型号表达 |
| 客户、员工 | 复用现有客户/员工主档，分别记录销售员、入库员和实际操作员 |

手机壳、钢化膜、数据线、充电头、耳机等是商品分类，厂家产品号才是商品型号；没有型号可不填。每种实际库存规格有唯一商品编码，同规格多供应商进货仍为一个商品的不同采购批次。

## 四、总仓、入库与门店调拨（用户确认）

2026-11-14实现补充：普通数量和SN入库均增加原采购持久请求防重；当前标签页关闭弹窗或刷新后，结果未确认的采购须使用原请求重试，不能另起一笔而重复库存和应付。回执使用原采购事实，不按后来变化的模板/库存重算；受控字段与唯一索引已于2026-11-14授权迁移回读，真实采购未验收。接口、权限、会话恢复限制及回滚保护见[采购入库防重](../backend/accessory-entry.md#采购入库防重与异常恢复)。

本轮实现补充（2026-11-13）：模板SN开关仅设默认，每次入库可独立切换，同模板允许SN与普通数量库存混合；SN模式隐藏总数并按实录条数计量，支持扫码/手动逐条与批量。同次统一进入提交时所选店铺，录入SN后仍可换店并保留草稿；不展示店铺/录入数量提示条、入库分配、适配字段、单位、状态、预警值、条形码和图片，模板保留对应资料。普通总数与入库员位于售价后，SN保留简洁开关。库存余量可查看店铺位置和SN；“设置”复用现有系统配置指定总仓，只改变入库默认值。店间划拨已按一次确认实现，仍不代表完整销售积分退款流程完成，详见[接口与迁移契约](../backend/accessory-entry.md#sn-入库库存追踪与总仓设置2026-11-13)。

后台可选择任意现有可用门店作为总仓，支持更换。总仓使用该门店的真实库存，不重复增加一个虚拟库存。更换总仓只改变配置和后续默认值，现有库存通过调拨移动，历史单据保持原门店。

采购支持直接入门店，也支持先入总仓再分配。总仓与门店、门店与门店之间均可互相调拨；这里的“划拨”指内部移库，与手机供应商划拨 `supplier_proxy` 的交易语义分别处理，不能沿用其零成本规则。调拨保留采购来源、成本及收费/赠送用途属性，不产生重复采购欠款。

入库记录至少覆盖供应商、入库门店、分类、品牌、商品名称/型号、适配机型、颜色及其他规格、数量、采购单价/总额、参考售价、入库员、业务日期、服务端记录时间、备注；按分类决定型号、颜色是否必填。

入库“收费/赠送”作为本次采购批次来源标记，不通过采购价是否为零推断，也不限制后续收费或赠送出库。2026-11-15核对现行出库及正式回归：两种用途库存均可按本次销售方式使用，无需新增“双用途”批次。免费使用的膜仍记录真实采购成本，普通数量按原批次分配，SN按实物来源追踪；实际出库批次、原用途和成本均保留。是否允许免费办理由模板及权限决定，不能通过改售价绕过赠送授权；模板免费标记不改写原采购用途、成本或历史单据。

内部调拨按用户后续确认采用操作员一次确认完成：来源店减库、接收店加库，同事务保留划拨及库存事实。库存流水覆盖每次入出库，数量不能为负或被重复提交扣减。商品分类、门店库存和用途变更应同步刷新相关选择器和列表缓存。

## 五、销售与单据（用户确认）

独立商品销售、手机搭售、赠送和贴膜使用同一套商品出库能力。商品销售后扣实际销售门店的对应规格/批次库存，赠送也记录成本和数量；手机与搭售商品、客户、收款、积分、库存及业务记录在同一事务中提交。

2026-11-13补充确认：批量手机销售保留一个公共备注框，提交后同一备注分别保存到每台手机及其销售记录；明确提交空备注时整批清空该销售备注。每台手机保留独立销售记录及单号。搭售/赠送商品通过名称搜索选中实际库存商品并填写数量，每条商品必须选择关联哪台手机，不能仅关联整批或依赖名称/备注猜测；SN商品指定实际出库SN。成功后同事务扣对应门店库存，供单台退货核对配件、赠品及积分。公共备注及手机逐台收款关联已实现；搭售选择与逐台商品关联仍以T22.3进度为准。

## 六、永久免费贴膜与跨店办理（用户确认）

手机销售补充规则：全新机和二手机每销售一台都自动尝试消耗一张当前型号适配的免费专用膜，销售门店作为出库门店；单台、批量、快速出库和共同结算保持同一事务。系统在存在唯一免费模板和唯一可用普通库存时生成零价赠送商品明细，并复用现有批次成本、库存流水及售后关联，不要求销售员额外拥有人工赠送权限。免费模板未配置、门店普通库存不足、结构尚未部署或实际品牌/颜色存在歧义时跳过自动贴膜，手机销售仍正常完成；批量销售按可用普通库存预留，SN膜不由自动流程扣除，须人工选择实际SN办理。该规则不改变综合查询中手动免费/收费贴膜的权限和历史服务记录口径。

2026-11-15专项实施：已将类型开关移至模板，贯通当前手机/客户关联、服务门店、免费唯一匹配及收费适配候选；多型号共用一模板库存。人工免费办理在缺配置、重叠或缺货时明确失败；手机销售随单自动贴膜遇到这些情况则跳过贴膜并继续销售。新增5列已按本次授权应用云端扩展并回读，后端已重启，模板开关仍为默认关闭，须显式配置后办理；真实业务尚未验收。当前代码契约见[贴膜后端正文](../backend/accessory-entry.md#贴膜服务后端与模板匹配)，验证及撤销公开入口状态统一跟踪T22.4。
