# 销售凭证展示与导出约定

本文记录综合查询销售凭证的业务展示和导出行为，适用于 `frontend/src/components/query/SalesReceipt.vue` 及其调用方 `frontend/src/views/query/QueryView.vue`，整单只读核对适用于 `frontend/src/components/query/CheckoutOrderDialog.vue` 及手机/商品详情入口。

## 凭证类型与内容

- 普通销售使用“销售凭证”，同行批发/调货使用“批发凭证”，供应商代划拨使用“划拨凭证”；三种类型分别使用对应主题色。
- 顶部居中显示凭证标题，凭证号码和销售时间并列展示。销售时间经全局 `TimeUtil` 按 `TIME_FORMATS.DISPLAY_DATE` 格式化。
- 客户、联系电话、供应商、销售门店和单据状态按凭证类型展示；划拨凭证不显示单据状态。
- 设备表格只展示实际凭证项目。设备标识优先显示 IMEI，没有 IMEI 时显示 SN；商品金额不显示千位分隔符。
- 汇总区域使用“总数量”、人民币大写和小写金额。人民币大写使用公共 `formatRmbUppercase`；小写金额不强制补 `.00`。
- 含随单配件时数量展示“手机台数 / 配件件数”。合计栏按内容分配两侧列宽并自适应高度，大写金额可换行；不得以固定行高裁切或叠盖数量、金额。手机继续纵向排列三个汇总字段。
- 销售、批发和划拨的售后说明根据业务类型分别展示，标题统一为“【售后说明】”。
- 合并凭证可以包含多个设备项目；凭证号码根据选中项目的单号显示单号、合并数量或合并单据数。

## 手机随单配件

普通零售手机凭证通过 `GET /query/sales/:saleId/accessories` 核对原手机销售的购买及赠送配件。接口沿用 `QueryGoodsController → QueryGoodsService → QueryGoodsRepository`，必须同时具有 `query:view`、`accessories:view`，并限制手机原销售及配件销售均在授权门店范围。按真实 `linked_phone_sale_id` 和原订单关联读取，不以客户手机号、商品名称或当前手机库存状态猜测归属；后续换货形成的新订单不混入原销售凭证。原配件已退货时仍保留原销售事实，售后在原单历史另行查看。

单次接口请求内，原配件明细与原出库SN使用同一只读一致性快照；查询期间并发提交的变化在下一次读取可见。合并多台手机仍分别请求各自原销售，不承诺多个请求共享数据库快照。

响应为配件只读投影，类型唯一来源为 `frontend/src/types/sales-receipt.ts` 的 `PhoneReceiptAccessory`，复用 `AccessorySaleDetail` 字段；包含原名称、实际品牌、配件型号、颜色、单位、数量、单价、原成交净额、购买/赠送用途、积分抵扣和原出库 SN，不返回采购成本或供应商。后端和前端继续使用配件公共字段权限，隐藏字段保持空值，不因打印补回。

手机表格后显示配件明细，并标出其关联手机；赠品显示“赠品”、数量和零成交金额。汇总分别显示手机台数和配件件数，金额按分相加：手机成交价加配件积分抵扣后的原实收，赠品不按参考售价计费。数量、用途或金额隐藏时不生成完整总金额，不能将未知金额当成零。

加载配件及核对失败期间禁用打印和图片保存，失败可重新核对；切换单据、关闭、卸载或撤回查看权限会废弃旧请求及明细。缺失原手机销售 ID 时要求从综合查询原销售记录重新打开，不能静默出具看似完整的凭证。无配件查看权限时不调用该接口，并在预览、打印及图片内明确“本凭证仅含手机”。批发/划拨继续沿用原凭证，不读取零售配件。

随单配件接口使用严格公共字段读取。角色/字段查询故障或配置损坏时返回统一错误，不返回未脱敏明细；前端按核对失败处理并禁止导出。此故障与合法隐藏字段分别处理，公共失败边界及回归见[字段权限指南](../frontend/field-permission-guide.md#后端边界)。

综合查询单条、多条及检索添加均保留 `sale_id`，同一销售的配件读取去重。SN/IMEI 检索沿用原接口的最新有效销售归属，不用取消的旧销售 ID 关联新凭证。此接口只读，使用已登记的共同结算/库存流水结构，不执行 DDL 或补造历史随单关系；尚未升级相应结构的环境必须先完成既有迁移。

正式回归位于 `backend/test/query-goods.check.js`、`backend/test/query-goods-snapshot.check.js`、`frontend/tests/sales-receipt-accessories.spec.ts`，覆盖购买与赠品、SN、抵扣合计、原单/门店/权限、旧请求失效、失败重试及打印/图片共用内容；组件测试不代表真实打印机或物理扫码设备验收。

## 图片保存与打印

- 图片导出通过公共 `loadHtml2Canvas` 按需加载 `html2canvas`，只在克隆文档中添加导出态样式，不改变页面正常展示。
- 手机导出展开表格全部列；配件名称、品牌型号和多个 SN 在各自单元格内换行，不允许长序列号覆盖相邻列。打印保留凭证外层和主题标记，长表格完整展开。
- 渐变文字的导出兼容样式只作用于克隆文档，防止截图引擎把渐变文字绘制成色块。
- 颜色兼容复用 `utils/html2canvas.ts` 的 `normalizeCanvasColors`，在凭证克隆展开后，将浏览器计算出的现代单色值转换为保留透明度的 sRGB。深色主题的公共序号徽章使用混色令牌，不能直接交给不支持 `color(...)` 的截图引擎；原页面及公共主题令牌不作改写。本入口处理文字、背景、边框、轮廓及文本装饰单色，不承诺转换现代渐变或阴影表达式。
- 导出使用 `canvas.toBlob()` 生成 PNG，通过临时下载链接触发下载，并释放 canvas、临时链接和 Blob URL。
- 保存过程中禁用重复触发并显示“正在生成图片”；完成或失败后恢复按钮状态，失败通过统一日志记录。
- 打印使用凭证内容和现有页面样式，打印覆盖规则只服务打印文档，不改变页面视图。
- 凭证纸面使用公共 `--tf-color-document-paper`，强调标题文字和公共表头使用不随主题反转的 `--tf-color-text-on-accent`；明暗主题下均保留浅色纸面及可读文字。

## 回归要求

调整凭证字段、主题、响应式布局、打印或图片导出后，至少检查销售、批发和划拨三种类型，并覆盖单条与多条设备。图片导出还应验证：

- 切换到另一条记录后连续保存两次，按钮状态及时反馈且每次都下载当前凭证。
- 导出图片中的内容完整、表格列对齐、金额与主题可读，渐变文字没有变成色块。
- PC 和手机视口下预览内容完整，打印内容没有被弹窗滚动区域裁切。

隔离浏览器入口为 `node frontend/scripts/test-checkout-order.mjs`，仅核对凭证可加 `--receipt-only`。脚本复用真实凭证、公共弹窗/样式和图片引擎，使用内存样本并阻断业务/外站网络；覆盖360/390/430/768/1440px明暗主题、购买/赠品/长SN及净额、三类凭证和合并手机打印、连续两次真实PNG下载、透明度保留、原页面颜色不变、撤权清理和失败重试。打印调用被拦截以核对新文档，不能据此声称物理打印机通过；下载、临时浏览器和Vite资源在结束时清理。

## 整单明细

综合查询的手机销售详情与商品销售详情共用“整单明细”只读弹窗。商品入口在有共同单的详情底部，已全退仍保留；手机入口使用原 `销售信息.sale_id`，不能用设备ID或客户手机号猜测原单。旧独立销售没有共同单时明确提示不存在，不生成模拟订单。

- `GET /query/goods/:id/order`：按真实商品销售ID定位。
- `GET /query/sales/:saleId/order`：按真实手机销售ID定位。

两入口均通过 `QueryGoodsController → QueryGoodsService → QueryGoodsRepository`，认证后要求 `query:view` 与 `accessories:view`。头及全部明细在同一只读一致性快照读取，完整核验原订单/销售/客户/门店/员工归属、商品数量/用途/原价、积分和SN；任一明细越出授权门店时整单拒绝，不能截成部分原单。读取原成交快照，不使用当前商品或手机资料替代；销售员名称经原订单员工ID解析，门店名经原门店ID解析。原销售已退不改变原单明细，换货后继单独成单并核验真实换货链，不混入原购买凭证。

展示共同单号、客户姓名及电话、销售门店/销售员/时间、整批备注、所有手机与商品明细、购买/赠送、原关联手机单号、原出库SN、数量/单位、单价/原金额/积分抵扣/原成交净额、消耗及获得积分。另列“本单现金入账”，换货新单含旧件抵付时可能小于原成交净额；它不是售后后累计净收入。售后仍到各商品原单历史查看。本入口不新增打印或图片系统，原手机销售凭证继续使用上文的随单配件投影。

字段严格按行来源分别脱敏：手机使用 `query_queryview`，商品使用 `accessories_accessoriesview`；共享客户/门店/员工/时间/备注在含手机单取两模块交集。隐藏商品用途、数量、单价或总价，或手机售价时，整单金额/积分合计同步返回null，不能通过相减反推被隐藏值。隐藏商品序号/单号时同步隐藏手机销售及关联单号。权限查询故障返回统一错误，不能降为全字段响应。前端响应校验保留合法null，缺项或资金不一致按失败处理；关闭/卸载/切源/撤权废弃请求及数据，失败可重试。

正式回归：`backend/test/checkout-order-query.check.js`、`frontend/tests/checkout-order.spec.ts`、`frontend/tests/query-goods.spec.ts`；隔离浏览器命令 `node frontend/scripts/test-checkout-order.mjs` 使用真实公共弹窗和样式、内存响应，检查360/390/430/768/1440px明暗主题、长SN及备注、撤权清理和重试。代码不新增表或迁移，不代表云端数据或物理设备验收。
