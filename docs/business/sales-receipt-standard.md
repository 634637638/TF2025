# 销售凭证展示与导出约定

本文记录综合查询销售凭证的业务展示和导出行为，适用于 `frontend/src/components/query/SalesReceipt.vue` 及其调用方 `frontend/src/views/query/QueryView.vue`，整单只读核对适用于 `frontend/src/components/query/CheckoutOrderDialog.vue` 及手机/商品详情入口。

## 凭证类型与内容

- 普通销售使用“销售凭证”，同行批发/调货使用“批发凭证”，供应商代划拨使用“划拨凭证”；三种类型分别使用对应主题色。
- 顶部居中显示凭证标题，凭证号码和销售时间并列展示。销售时间经全局 `TimeUtil` 按 `TIME_FORMATS.DISPLAY_DATE` 格式化。
- 客户、联系电话、供应商、销售门店和单据状态按凭证类型展示；划拨凭证不显示单据状态。
- 手机及随单配件共用一张表和一组表头；手机行后以跨列分隔行标识“配件 / 赠品明细”。设备标识优先显示 IMEI，没有 IMEI 时显示 SN；手机规格列将颜色、内存和成色用独立斜杠分隔，成色复用公共 `condition-badge` 的全新/二手语义色；商品金额不显示千位分隔符。
- 汇总区域使用“总数量”、人民币大写和小写金额。人民币大写使用公共 `formatRmbUppercase`；小写金额不强制补 `.00`。
- 含随单配件时数量展示“手机台数 / 配件件数”。合计栏按内容分配两侧列宽并自适应高度，大写金额可换行；不得以固定行高裁切或叠盖数量、金额。手机继续纵向排列三个汇总字段。
- 销售、批发和划拨的售后说明根据业务类型分别展示，标题统一为“【售后说明】”。
- 合并凭证可以包含多个设备项目；凭证号码根据选中项目的单号显示单号、合并数量或合并单据数。

## 手机随单配件

普通零售手机凭证通过 `GET /query/sales/:saleId/accessories` 核对原手机销售的购买及赠送配件。接口沿用 `QueryGoodsController → QueryGoodsService → QueryGoodsRepository`，必须同时具有 `query:view`、`query:goods-view`，并限制手机原销售及配件销售均在授权门店范围。按真实 `linked_phone_sale_id` 和原订单关联读取，不以客户手机号、商品名称或当前手机库存状态猜测归属；后续换货形成的新订单不混入原销售凭证。部分退货时凭证按未退数量及对应原成交净额展示，全部退货的商品行从凭证移除，已退SN不再展示；综合查询商品模式仍保留原销售记录，并通过已退/剩余数量及原单售后历史追溯退货明细。

单次接口请求内，原配件明细与原出库SN使用同一只读一致性快照；查询期间并发提交的变化在下一次读取可见。合并多台手机仍分别请求各自原销售，不承诺多个请求共享数据库快照。

响应为配件只读投影，类型唯一来源为 `frontend/src/types/sales-receipt.ts` 的 `PhoneReceiptAccessory`，复用 `AccessorySaleDetail` 字段及 `sales-checkout.ts` 的 `GiftReturnAgreement`；包含原名称、实际品牌、配件型号、颜色、单位、数量、单价、原成交净额、购买/赠送用途、积分抵扣、原出库 SN 及赠品未退约定，不返回采购成本或供应商。销售凭据页面不展示赠品未退约定文案，但保留其响应校验，隐藏字段保持空值，不因打印补回。

配件行以“关联：设备号”标出关联手机，并标出原出库SN；金额区只显示原成交净额作为实收。赠送行使用灰色实收金额，例如“实收 ¥0”，不按参考售价计费。金额合计仍按分相加手机成交价和配件原实收。数量、用途或金额隐藏时不生成完整总金额，不能将未知金额当成零。

赠品未退约定从原成交快照 `gift_return_unit_price` 解析，后端与售后复用 `readGiftReturnAgreement`，前端与整单明细共用校验和文案。响应 `gift_return_unit_price/gift_return_total/gift_agreement_state` 区分缺失或NULL（`not_recorded`，显示“原单未记录约定金额”）与明确零元（`recorded`，显示原单约定¥0）；合计按原数量和整数分计算。约定不计入实收，也不表示已扣款，明确提示“实际扣款以售后核对为准”，不能取当前售价补齐。用途、数量、单价、总额任一隐藏，三个派生字段同步NULL且不显示约定；坏快照或金额数量不一致按核对失败处理，禁止打印和图片保存。

首次核对及重试期间保留凭证内容，使用[全局加载规范](../frontend/global-loading-standard.md)的 `LoadingOverlay` 在凭证正文内居中显示“正在核对随单配件...”。加载配件及核对失败期间禁用打印和图片保存，失败可重新核对；切换单据、关闭、卸载或撤回查看权限会废弃旧请求及明细。缺失原手机销售 ID 时要求从综合查询原销售记录重新打开，不能静默出具看似完整的凭证。无配件查看权限时不调用该接口，并在预览、打印及图片内明确“本凭证仅含手机”。批发/划拨继续沿用原凭证，不读取零售配件。

随单配件接口使用严格公共字段读取。角色/字段查询故障或配置损坏时返回统一错误，不返回未脱敏明细；前端按核对失败处理并禁止导出。此故障与合法隐藏字段分别处理，公共失败边界及回归见[字段权限指南](../frontend/field-permission-guide.md#后端边界)。

综合查询单条、多条及检索添加均保留 `sale_id`，同一销售的配件读取去重。SN/IMEI 检索沿用原接口的最新有效销售归属，不用取消的旧销售 ID 关联新凭证。此接口只读，使用已登记的共同结算/库存流水结构，不执行 DDL 或补造历史随单关系；尚未升级相应结构的环境必须先完成既有迁移。

正式回归位于 `backend/test/query-goods.check.js`、`backend/test/query-goods-snapshot.check.js`、`frontend/tests/sales-receipt-accessories.spec.ts`，覆盖购买与赠品、部分/全部退货、剩余SN、逐件积分抵扣、原单/门店/权限、旧请求失效、失败重试及预览/打印/图片导出一致；组件测试不代表真实打印机或物理扫码设备验收。

## 图片保存与打印

- 图片导出通过公共 `loadHtml2Canvas` 按需加载 `html2canvas`，只在克隆文档中添加导出态样式，不改变页面正常展示。
- 手机导出展开表格全部列；配件名称、品牌型号和多个 SN 在各自单元格内换行，不允许长序列号覆盖相邻列。打印保留凭证外层和主题标记，长表格完整展开。
- 渐变文字的导出兼容样式只作用于克隆文档，防止截图引擎把渐变文字绘制成色块。
- 颜色兼容复用 `utils/html2canvas.ts` 的 `normalizeCanvasColors`，在凭证克隆展开后，将浏览器计算出的现代单色值转换为保留透明度的 sRGB。深色主题的公共序号徽章使用混色令牌，不能直接交给不支持 `color(...)` 的截图引擎；原页面及公共主题令牌不作改写。本入口处理文字、背景、边框、轮廓及文本装饰单色，不承诺转换现代渐变或阴影表达式。
- 导出使用 `canvas.toBlob()` 生成 PNG，通过临时下载链接触发下载，并释放 canvas、临时链接和 Blob URL。
- 保存过程中禁用重复触发并显示“正在生成图片”；完成或失败后恢复按钮状态，失败通过统一日志记录。
- 打印通过公共 `frontend/src/utils/print.ts` 复制凭证DOM与现有页面样式；使用DOM设置标题及复制节点，避免将客户文字拼入HTML。打印覆盖规则只服务独立打印文档，不改变页面视图。
- 凭证纸面使用公共 `--tf-color-document-paper`，强调标题文字和公共表头使用不随主题反转的 `--tf-color-text-on-accent`；明暗主题下均保留浅色纸面及可读文字。

## 回归要求

调整凭证字段、主题、响应式布局、打印或图片导出后，至少检查销售、批发和划拨三种类型，并覆盖单条与多条设备。图片导出还应验证：

- 切换到另一条记录后连续保存两次，按钮状态及时反馈且每次都下载当前凭证。
- 导出图片中的内容完整、表格列对齐、金额与主题可读，渐变文字没有变成色块。
- PC 和手机视口下预览内容完整，打印内容没有被弹窗滚动区域裁切。
- 配件读取尚未返回时，首次打开和手动重试的圆环与文案在正文内居中，文案保持单行，打印和保存图片不可用。

隔离浏览器入口为 `node frontend/scripts/test-checkout-order.mjs`，仅核对凭证可加 `--receipt-only`，同时核对整单与凭证可加 `--documents-only`。脚本复用真实凭证、公共弹窗/样式和图片引擎，使用内存样本并阻断业务/外站网络；覆盖360/390/430/768/1440px明暗主题、购买/赠品/长SN及净额、三类凭证和合并手机打印、连续两次真实PNG下载、透明度保留、原页面颜色不变、撤权清理和失败重试。打印调用被拦截以核对新文档，不能据此声称物理打印机通过；下载、临时浏览器和Vite资源在结束时清理。

## 整单明细

综合查询的手机销售详情与商品销售详情共用“整单明细”只读弹窗。商品入口在有共同单的详情底部，已全退仍保留；手机入口使用原 `销售信息.sale_id`，不能用设备ID或客户手机号猜测原单。手机查询响应的 `sale_info.has_checkout_order` 为布尔值，按当前销售ID关联手机明细及已完成、有结算请求标识的真实共同单；仅为true时显示入口，旧独立销售、无销售及缺少标记的响应不显示，避免点击必然不存在的原单。切换销售或关联标记失效时清理子弹窗。此标记不替代原单接口的权限、门店及完整事实校验；直接查询无共同单的销售仍返回404，不生成模拟订单。

- `GET /query/goods/:id/order`：按真实商品销售ID定位。
- `GET /query/sales/:saleId/order`：按真实手机销售ID定位。

两入口均通过 `QueryGoodsController → QueryGoodsService → QueryGoodsRepository`，认证后要求 `query:view` 与 `query:goods-view`。头及全部明细在同一只读一致性快照读取，完整核验原订单/销售/客户/门店/员工归属、商品数量/用途/原价、积分和SN；任一明细越出授权门店时整单拒绝，不能截成部分原单。读取原成交快照，不使用当前商品或手机资料替代；销售员名称经原订单员工ID解析，门店名经原门店ID解析。原销售已退不改变原单明细，换货后继单独成单并核验真实换货链，不混入原购买凭证。

展示共同单号、客户姓名及电话、销售门店/销售员/时间、整批备注、所有手机与商品明细、购买/赠送、原关联手机单号、原出库SN、数量/单位、单价/原金额/积分抵扣/原成交净额及消耗和获得积分。赠品未退约定仍按上文校验，但不在销售凭据中展示，不计入原成交或现金入账。另列“本单现金入账”，换货新单含旧件抵付时可能小于原成交净额；它不是售后后累计净收入。售后仍到各商品原单历史查看。整单默认仍为只读明细；商品收银成功后可用销售凭证模式查看并打印。它按结算响应中的真实商品销售ID读取上述原单接口，不使用购物草稿生成成交凭证；读取失败可重试，加载、失败及撤权期间禁止打印。原手机销售凭证继续使用上文的随单配件投影。两入口复用 `utils/print.ts` 的独立文档打印，复制已授权DOM与样式，不额外读取或补齐字段；业务打印覆盖只用于相应独立凭证窗口，不改变原页面。

字段严格按行来源分别脱敏：手机使用 `query_queryview`，商品使用 `query_queryview` 的 `goods` 字段子范围（用户读取键 `query_goods`）；共享客户/门店/员工/时间/备注在含手机单取两模块交集。隐藏商品用途、数量、单价或总价，或手机售价时，整单金额/积分合计同步返回null，不能通过相减反推被隐藏值。隐藏商品序号/单号时同步隐藏手机销售及关联单号。权限查询故障返回统一错误，不能降为全字段响应。前端响应校验保留合法null，缺项或资金不一致按失败处理；关闭/卸载/切源/撤权废弃请求及数据，失败可重试。

正式回归：`backend/test/checkout-order-query.check.js`、`backend/test/sale-status.check.js`、`frontend/tests/checkout-order.spec.ts`、`frontend/tests/query-goods.spec.ts`；隔离浏览器命令 `node frontend/scripts/test-checkout-order.mjs` 使用真实公共弹窗和样式、内存响应，检查360/390/430/768/1440px明暗主题、长SN及备注、撤权清理和重试。手机详情入口专项加 `--phone-detail-only`，覆盖普通销售零原单请求、共同单按销售ID读取及切换后关闭。代码不新增表或迁移，不代表云端数据或物理设备验收。
