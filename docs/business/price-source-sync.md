# 报价多来源采集规则

## 来源配置

报价管理的同步源支持两类：

- `登录账户`：使用配置的登录地址、用户名和密码采集，例如 3333、3335。
- `公开未登录`：不执行登录，使用数据源公开访问结果采集。

每个来源都有独立的 Cookie、同步日志和来源价格记录。调度器会为所有启用同步间隔的来源建立独立任务。

## 商品来源选择

价目表商品的“采集来源”有以下规则：

- `跟随默认采集源`：商品的 `source_config_id` 为空，使用当前默认来源。
- 指定某个来源：只有该来源同步时更新这条商品的当前价格。
- `公开未登录`：系统会在已有默认数据源时自动初始化一条非默认公开来源；也可以在同步设置中修改它的数据源 URL。

例如默认来源是 3333，只有 iPhone 18 Pro Max 256GB 白色指定为 3335，则其他商品继续使用 3333，该商品使用 3335。公开来源也可以按同样方式指定。

主价目表仍然只保留一条商品当前展示价格，不会因为多个来源产生重复商品。各来源的原始批发价保存在 `price_source_prices`，用于追溯和防止来源之间互相覆盖。

## 加价和公开报价

采集流程先保存来源批发价，再按既有模板加价规则和全局加价规则计算销售价。来源切换不会绕过加价配置；例如批发价统一加价 30，不论价格来自 3333、3335 还是公开来源，均按同一规则计算。

顶部“同步”统一执行“同步全部来源”，使用同一个同步批次时间。公开报价按商品当前来源分别判断该来源的最新同步批次，因此不同来源完成时间不同也不会让其他来源的商品被整体隐藏。

## 批次和公开展示口径

- 手动点击“同步全部来源”时，3333、3335 和公开来源会共用同一个 `sync_batch_id` 与同步时间；因此这次操作产生的是同一批数据。
- 顶部同步不会只同步默认来源。系统会遍历全部已配置来源：未指定来源的商品由当前默认来源更新，指定 3335 或公开来源的商品由对应来源更新。
- 定时同步按来源独立执行，不要求不同来源在同一秒完成。公开报价会分别取商品当前采集来源的最新成功批次，3333 的最新批次和 3335 的最新批次可以有不同时间，但都会正常展示。
- 公开页面不会把多个来源合并成多条商品，也不会要求整张价目表的时间完全相同。每个商品仍只展示其当前来源采集到的那一条价格。
- 商品切换采集来源后，建议执行一次对应来源同步；在新来源尚未成功采集前，公开页面仍遵守原有“最新同步时间”规则，不会把其他来源的价格复制过来。
- 保存商品来源只保存“以后由谁采集”的绑定关系，不会把另一来源的旧采集价瞬间复制到主价目表；执行该来源同步后，主价目表才会更新为新来源价格。

首次启用本功能时，服务启动会自动检查并补充 `price_sync_config.source_type`、`price_list.source_config_id` 和 `price_source_prices` 结构。也可以在 `backend` 目录执行 `npm run migrate:price-sources` 显式迁移。生产环境建议在发布后检查启动日志，确认结构检查成功，再执行一次“同步全部来源”。
