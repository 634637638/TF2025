# 型号检索统一规范

## 目的

型号属于品牌下的从属选项。业务页面不应在打开页面或编辑弹窗时一次加载全部型号，而应先确定品牌，再按品牌和关键词检索型号。

## 统一流程

1. 先选择品牌，型号请求必须携带 `brand_id`。
2. 输入型号关键词后携带 `name` 进行远程检索。
3. 前端使用防抖或请求序列号丢弃旧响应，避免快速输入时旧结果覆盖新结果。
4. 编辑已有设备时携带 `include_id`，确保当前型号即使不在前 50 条也能回显。
5. 后端最多返回 50 条，并统一按 `sort_order`、型号名称、ID 排序。
6. 未选择品牌时不请求型号列表。

## 公共接口

后台业务页面使用：

```text
GET /api/query/models?brand_id=品牌ID&page_size=50&name=关键词&include_id=当前型号ID
```

该接口使用综合查询查看权限，返回标准型号字段：`id`、`name`、`brand_id`、`brand_name`、`sort_order`。

前端公共入口为 `frontend/src/services/reference-options.ts` 中的 `getCachedModelsByBrand`。入库、综合查询筛选和综合查询编辑应复用该入口或同等的品牌型号请求，不得恢复 `page_size=10000` 全量加载。

## 例外

型号管理页面自身仍可使用分页列表，用于管理和排序全部型号。这个管理列表与业务表单的远程下拉不是同一个加载场景。
