# 页面权限能力统一规范

> **唯一能力清单**：`backend/src/config/module-permission-capabilities.json`
> **强制审计**：`cd frontend && npm run check:permissions`  
> **适用范围**：受登录保护的页面、页面按钮、弹窗操作、批量操作和对应后端接口

## 目标

权限必须描述页面真实存在的业务能力。页面没有“管理”或“同步”功能时，不得因为通用模板而生成 `manage`、`sync`；页面只有查看能力时，只能登记 `view`。

共享能力清单是前端、后端和模块扫描器的唯一权限动作来源。数据库中的旧权限记录只能用于角色已分配状态，不能反向创造页面能力。

## 权限判定规则

| 动作 | 允许登记的条件 |
| --- | --- |
| `view` | 受保护页面需要被访问和读取数据，所有模块必有 |
| `create` | 页面确实能新增一条业务记录 |
| `edit` | 页面确实能修改已有业务记录 |
| `edit-history` | 租赁非进行中合同更正，须同时具备该模块 `edit`；不以角色编码放行 |
| `delete` | 页面确实能删除或清理业务记录 |
| `approve` | 存在独立审批动作，不得用 `edit` 代替 |
| `manage` | 存在无法归入普通 CRUD 的独立管理功能，例如分类管理；不得作为管理员兜底 |
| `export` / `import` | 页面存在真实导出或导入入口及接口 |
| `sync` | 页面存在用户主动触发的同步操作和独立接口 |
| `match` / `deliver` / `cancel` | 预定等业务存在对应独立状态流转 |
| `return-to-stock` | 存在真实退库业务动作 |
| `exchange` | 综合查询存在按原单退旧件、换新件和结算净差价的独立商品换货；不以退库权限替代 |
| `gift` / `transfer` | 配件存在独立赠送出库或店间库存划拨，不能以入库/编辑权限替代 |
| `goods-view` / `goods-sell` / `goods-gift` | 综合查询商品模式分别控制只读查询、收费销售、赠送；依赖本页查看及商品查询，不授予商品管理页面查看、入库或编辑 |
| `film` | 综合查询的专用客户贴膜办理（含免费/收费）及指定客户跨店最小服务历史；核验客户设备关联、适配、字段及服务门店库存，不要求商品管理查看/新增/赠送，不授权普通商品出库或其他页面 |
| `wholesale` / `proxy-transfer` | 销售模块存在对应独立出库流程 |

`manage` 只授予对应模块的明确管理操作，不能提升为系统管理员、模块通配或其他模块权限。客户编辑不隐含客户管理；`permissions:admin` 只接受明确管理授权或权限模块完整 view/create/edit/delete 集合，单项查看/编辑或模块管理查看不构成系统管理授权。

“按钮只给管理员看”不是登记 `manage` 的理由。按钮是什么业务动作，就使用什么动作权限；管理员同样通过角色授权获得该权限。

## 动作按钮与字段权限

- 页面动作权限决定按钮和操作是否可用；字段权限只决定业务数据是否展示，二者不能互相代替。
- 编辑、删除、审批、到账、上传等按钮必须只按各自动作权限显示，关闭权限时直接隐藏，不展示禁用占位按钮。
- 所有业务操作列、卡片操作区和手机详情底部操作区统一调用 `shouldShowActionColumn(fieldVisible, actionPermissions)`：字段可见或至少一个对应动作获权时展示；操作字段隐藏时，已获权的操作仍保留入口。禁止页面自行使用“操作字段可见 AND 动作权限”的组合条件。
- 操作列容器按“字段可见 OR 任一列内动作获权”显示；列内每个按钮仍只按自己的动作权限显示。普通数据字段仍只按字段权限显示，不能使用操作列规则放开。
- 动作必须放在语义对应的字段列：审批放在审批/提交列，到账放在到账列，上传放在图片列；通用操作列只放编辑、删除等没有独立业务字段的动作。
- 隐藏审批时间、到账时间等数据字段，不得隐藏已获权的审批、到账按钮，但按钮必须留在各自字段列；后端仍分别使用 `requirePermission` 返回 403。
- 隐藏图片等敏感字段时，普通列表和详情继续掩码；独立上传权限可保留上传入口，并通过只授予上传角色的专用接口读取管理所需数据。
- 前端隐藏按钮不是安全边界。所有写接口、状态流转接口、上传接口仍必须使用与按钮一致的后端动作守卫。
- `v-permission` 接收单个权限名，或 `{ permission: ['模块:动作', ...], mode: 'any' | 'all' }`；数组默认任一获权显示，`all` 逐项校验。每项分别解析模块通配与统一权限别名，不能让某个模块的通配代替其他模块权限；权限更新后指令同步显示状态。综合查询商品销售入口以本页商品销售或商品赠送任一获权显示，后端仍逐条检查实际动作。
- 字段权限必须贯穿列表、选项接口、详情、打印、导出和写接口。后端不得先返回完整敏感对象再依赖前端隐藏。
- 通用编辑只提交可见字段，后端对隐藏字段返回 `403 FIELD_PERMISSION_DENIED`；动作执行所必需的状态字段只能在拥有该动作权限时作为明确例外保留。

### 权限开关布局

- 页面权限配置中的“菜单查看”和动作权限使用统一权限开关卡片，不允许按页面固定按钮宽度。
- 权限开关区域必须按按钮内容计算最小必要宽度，使用流式换行排列；不能固定成统一宽度、通过省略号隐藏权限名称或把开关挤出容器。
- 屏幕空间不足时，单个按钮才收缩到容器宽度并允许文字换行；开关轨道保持固定触控尺寸。

### 当前角色动作批量开关

- 页面权限配置中的批量开启/关闭只作用于当前选中的角色，不得批量修改其他角色。
- 批量动作只能针对共享能力清单中、当前权限矩阵实际已注册的业务动作，例如编辑、新增、删除；`view` 和 `menu_view` 不属于批量业务动作。
- 关闭某个动作时，只移除当前角色各相关模块的该动作权限键，例如 `sales_salesview:edit`；当前角色的查看、菜单显示和其他动作必须保留。
- 开启某个动作时，只补充当前权限矩阵中支持该动作的模块，不得覆盖当前角色已有的其他权限。
- 批量操作继续使用现有角色权限替换接口保存，前端不得新增“修改全部角色”或绕过角色权限校验的接口。
- 批量关闭必须使用统一确认提示，并在保存失败时恢复当前角色的界面状态。

## 单一来源

- 模块及动作只在 `backend/src/config/module-permission-capabilities.json` 登记。
- `backend/src/config/module-permission-actions.js` 只读取清单，不再维护动作数组或模块中文元数据。模块中文名称、说明在清单 `moduleMetadata`，动作中文名称和说明在 `actionLabels/actionDefinitions`；前端权限开关、操作日志、无权提示（含统一请求错误及权限提示服务）和后端注册、扫描及空库备用清单共用它们。不得另建名称表。
- `frontend/src/config/modules.ts` 和 `frontend/src/utils/permissionMapper.ts` 必须从清单派生，不得复制权限数组。
- 新增模块除了登记共享能力清单，还必须在 `frontend/src/utils/permissionMapper.ts` 增加完整模块标识到前端短名称的反向映射；否则后端返回的完整权限和路由使用的短权限无法归一，页面会错误提示无权限。
- 未登记模块运行时只能回退为 `view`，审计时受保护路由页面未登记会直接失败。
- `menu_view` 是导航入口权限，不是页面业务动作，不写入模块动作数组。

## 页面、数据范围与动作三层边界

1. 母页面 `view` 只控制入口；独立业务 TAB 必须使用自己的查看和动作权限。
2. 本人和团队查看分别限制数据对象。`menu_view` 仅控制导航，不能转为 `view`；本人查看不能放行团队分析。团队查看不授予替他人新增。
3. 新增、编辑、删除、审批、发放分别校验真实动作。模块 `manage` 不构成系统权限管理员；系统权限管理继续使用统一 `permissions:admin` 判定。

### 管理店铺与业务数据范围

“管理店铺”只限定当前用户可查看、选择和操作的门店，不授予页面或动作。所有范围判定复用后端 `utils/store-scope.js`：普通用户未绑定时列表为空，指定未授权门店或写入时返回403；具备完整权限管理授权的管理员保留全店范围。门店管理、用户绑定管理使用 `getStores()` 获取管理端完整选项，业务表单使用 `getStores({ strictScope: true })` 获取当前范围。

| 业务 | 范围依据与写入核验 |
| --- | --- |
| 手机库存、可售候选、库存汇总/明细、采购货款 | 手机来源门店 `phones.store_id`；列表、统计、导出和明细同口径 |
| 普通/批量手机销售 | 同时核验每台来源店、表单销售店；两店可不同，批量任何设备越界整单回滚；附加商品扣所选销售店库存 |
| 预定 | 列表、统计、详情及订单动作按预定店；自动/手动匹配与释放设备也核验设备来源店；更换店铺核验新旧范围 |
| 国补 | 列表、详情、筛选、导出、统计、审批、到账、照片及更正按国补单门店；设备候选和新建时另核验有效销售单门店及客户关联 |
| 租赁 | 买断关联销售门店，其他合同用设备门店；正文、合同附件、还款及归还同范围；创建另核验设备来源店，改成本或返库再核验来源店 |
| 手机货款 | 按采购来源店；登记/撤销逐台核验，批次编辑覆盖的全部手机必须授权，不能只修改其中合法部分 |
| 仪表盘与销售分析 | 库存、入库及采购预警按来源店，销售统计、排行、动态按销售店；维修动态按维修店；预警候选与外层聚合使用相同范围 |

客户主档、品牌、型号、颜色及模板仍是共享资料；相关交易继续按业务门店控制。工资和考勤仍使用本人/团队范围，不能把绑定门店转成全店员工管理权。业务门店及带门店的查询选项不使用前端持久缓存；绑定写入及身份失效规则见[权限缓存刷新](../permissions/permission-cache-refresh.md)。

### 跨模块授权处置

| 场景 | 授权边界 |
| --- | --- |
| 综合查询商品、客户商品历史、共同单与关联商品 | 使用 `query:view/goods-view`，客户页面仍须客户查看；字段权限继续复用商品字段，不开放商品管理 |
| 收费商品与赠送（独立、搭售、快速出库） | 商品管理使用 `accessories:view` 加 `sell/gift`；或查询 `view/goods-view` 加 `goods-sell/goods-gift`；手机部分另核验手机销售权限 |
| 商品售后和带商品手机售后 | 查询商品查看及对应 `return-to-stock/exchange`；换出商品另核验实际销售/赠送动作和门店、字段 |
| 客户贴膜历史及办理 | 客户入口保留客户查看，服务使用查询 `view/film` 及客户关联；不授予商品管理 |
| 业务客户检索、新增与编辑 | 候选检索用业务专用权限；新建独立 `customers:create`，改已有档案独立 `customers:edit`，不要求开放客户管理 `view`；销售/快速出库/共同结算/批发/设备编辑内部写客户同样检查。组件及拒绝场景见[客户检索规范](customer-search-standard.md#客户操作权限) |
| 商品档案、采购入库 | `accessories:create` 与 `accessories:stock-in` 分开；入库不能授予销售 |
| 采购退供核对、试算 | `supplier-payments:view` 加商品查看或独立 `return-check`，继续核验字段及采购/门店范围；没有正式提交退供接口 |
| 首页商品预警 | 首页查看加商品查看或 `dashboard:goods-warning`，仅返回名称、库存、阈值及状态摘要，仍核验字段 |
| 分析源业务 | 库存、客户分别需源业务查看；员工工资分析需团队 `salary-records:view`；考勤单独按本人/团队范围过滤，全员出勤率另需团队考勤查看 |
| 工资管理 | 母页面、我的工资、工资模板、工资计算分开；工资计算的新增/编辑/删除/审批/发放分别授权；工资页考勤按钮及提交使用考勤权限 |
| 工资读取复核 | 列表、详情、员工工资候选及当前底薪在复核无查看权限时停止查询；本人列表强制当前员工已发范围，不得将无权限范围当作全量 |
| 工资模板选项与绑定 | 启用模板选项需 `salary-templates:view` 或团队 `salary-records:view`；员工及旧用户创建/编辑提交模板绑定（含null清除）另须 `salary-templates:edit`，普通员工编辑不能代替 |
| 考勤组合授权 | 本人申请只允许本人；团队查看加本人申请仍不能替别人新增，必须有团队考勤新增；改审批状态需审批权限 |
| 模块管理 | 普通列表/详情用模块查看、常规编辑用模块编辑；新增/删除另须权限管理员，扫描/注册/同步维持权限管理员授权 |
| 数据导入 | 独立 `data-import:view/upload/import/delete`，母页面数据优化不能替代；后端历史 execute 入口统一映射 import |
| 旧用户写接口 | `/users` 创建/编辑携带 `role_ids/role_id/role` 必须另有 `permissions:admin`；通过公共角色分配服务与账号同事务提交、提交后审计。普通资料编辑无须角色授权，但不能修改、删除或停用其他权限管理员账户 |
| 租赁历史更正 | `active` 合同用 `rentals:edit`；其他状态另需 `rentals:edit-history`；不按 `admin` 角色编码、角色名称或层级放行，隐藏字段及交易约束继续有效 |
| 员工角色 | 角色候选用员工专用最小接口；真实角色新增、修改、分配及移除需权限管理员并审计。普通员工编辑不得修改权限管理员账户 |
| 商城 | 模板、已售、配置、轮播、订单分别用子模块权限；销售、库存及商城母模块不能替代。库存发布入口继续使用库存动作并核验设备门店及图片归属 |
| 手机通用编辑/删除 | 按原状态判定库存或交易动作，逐字段检查，并同时核验原门店与目标门店；不能借库存编辑修改已销售记录 |
| 保留的合理共享 | 手机/商品货款仍共用供应商货款岗位动作；手机预警仍用系统设置；手机入库仍允许入库新增或库存新增。共享不提升为系统管理员 |

### 发布与角色配置

发布必须同时更新前后端及共享能力清单；模块同步注册独立数据导入、租赁历史合同更正和其他新动作后，由管理员按岗位明确分配。普通角色不自动补入库、销售、发放、商品预警或退供核对权限，菜单权限也不自动补业务查看。既有自定义模块名保留；自动名称从权威元数据同步，工资子模块统一称“工资计算”，模块键不变。同步不会迁移交易数据。

权限/角色/账户及门店绑定写入后清理服务端身份缓存，统一认证读取当前门店绑定，旧 JWT 不得恢复已解绑门店。前端缓存仅用于恢复登录上下文，身份及权限响应均通过核验后才允许公共路由和指令授权，核验中或失败时拒绝；详见[缓存刷新](../permissions/permission-cache-refresh.md)。前端仍通过公共权限刷新恢复界面；不得以浏览器隐藏作为安全边界。行为回归入口为 `backend/test/permission-boundaries.check.js`、`backend/test/auth-profile-invalidation.check.js`、`backend/test/phone-resource-access.check.js` 及前端 `permission-mapper-boundaries.spec.ts`、`salary-payout-paid.spec.ts`。这些隔离测试不代表云端真实角色和真机验收。

## 新增与维护页面的权限登记门槛

新增、维护、拆分、合并或迁移页面时，页面权限和字段权限都是同一项交付要求，必须在提交或打包前形成完整闭环。只完成菜单、路由或按钮权限登记，未完成字段登记和运行时接入的页面，不视为完成。

每次变更至少核对以下内容：

1. 页面入口、路由、菜单、母子归属和稳定的 `module_key`；页面真实存在的动作只登记到共享能力清单。
2. 页面动作权限：前端使用 `usePagePermissions(moduleAlias)` 或 `PermissionGate`，按钮和处理函数校验同一动作；后端写接口使用 `requirePermission('moduleAlias:action')`，不能只隐藏前端按钮。
3. 字段权限登记：所有可展示、可筛选、可提交和可编辑的业务字段登记在唯一字段清单（`frontend/src/config/moduleFields.js`）及对应字段契约中；统计、ID、操作列、只读快照和派生值不得伪装成可编辑字段。
4. 字段运行时接入：前端列表、详情、表单和弹窗复用 `useFieldPermissions`/公共字段入口；隐藏、只读、编辑三态必须实际影响展示和控件；后端响应脱敏及写入拒绝复用 `FieldAccessService`，不能用前端隐藏替代服务端检查。
5. 维护已有页面时，同步检查新增或变更字段是否更新字段登记、前后端映射、字段契约和相关行为测试；删除或改名字段时清理旧登记、接口映射和页面引用，避免遗留权限继续生效。
6. 同步更新页面与功能单元台账、权限映射和必要文档；执行 `npm run check:permissions`、`npm run check:field-permissions`、`npm run check:standards` 及适用的前后端行为测试，全部通过后才能提交或打包。

字段三态语义、配置格式、多角色合并和后端拒写边界以[字段权限使用指南](field-permission-guide.md)为准；本节规定新增和维护页面必须完成登记、接入与审计，不改变页面动作权限与字段权限相互独立的原则。

## 新增页面流程

1. 在路由中注册真实页面。弹窗和纯展示/筛选 Tab 沿用所属页面模块；具有独立数据、接口和业务职责的 Tab 必须建立独立模块。
2. 确定稳定的 `module_key`，在共享能力清单中只登记页面真实存在的动作。
3. 页面使用 `usePagePermissions(moduleAlias)`；按钮显示、点击处理函数都校验同一动作。
4. 后端写接口使用 `requirePermission('moduleAlias:action')` 校验相同动作，不能只隐藏前端按钮。
   新增动作使用短模块别名时，同步核对 `backend/src/config/permission-mapping.js` 能将角色保存的完整 `module_key:action` 映射到该别名；仅在能力清单登记动作或前端识别成功不代表后端能通过。使用真实统一鉴权中间件验证已授权通过、未授权拒绝，不能只注入始终返回成功的权限替身。
5. 如需简短模块名，在统一映射中添加兼容别名；不得建立“入库弹窗”“编辑弹窗”等虚假模块。
6. 运行 `npm run check:permissions` 和 `npm run check:standards`，全部通过后才能提交或打包。

## 修改或移除功能

- 新增按钮或接口时，先判断是否已有准确动作；没有时先在 `actionDefinitions` 和 `actionOrder` 定义，补齐 `actionLabels` 中文名称，再登记到目标模块。
- 移除页面功能时，同时移除按钮、处理函数、接口授权映射和共享清单动作。
- 业务动作改名时，前端按钮、处理函数、后端接口、权限日志和能力清单必须一起修改。
- 数据库遗留的旧角色权限不得继续显示为可配置按钮；需要通过迁移或权限同步清理。
- `role_type=admin` 的启用角色在模块同步时获得该模块清单内的全部真实动作和 `menu_view`；普通角色仍按明确分配控制。
- 禁止根据“销售员、员工、经理”等角色名称给新模块自动授权；模块同步不得扩大普通角色的权限范围。

## 公开页面和容器页面

- 无需登录的公开页面登记在 `publicPages`，不得生成角色权限模块。
- 仅承载子路由的布局页面登记在 `scanExcludedPages`，不生成独立模块。
- 子组件、普通弹窗和纯展示/筛选 Tab 使用所属页面权限；独立业务页面及独立业务 Tab 按下面的模块登记与查看权限规则处理。

## 页面与独立 TAB 的查看权限

### 母页面、子页面与权限模块

本节是全站母子页面权限归属与展示的权威规则；模块扫描文档负责识别可注册页面，不另行定义母子关系。必须分别判断业务归属与鉴权边界：

| 对象 | 判定依据 | 页面权限展示及鉴权 |
| --- | --- | --- |
| 母页面 | 某个业务域的主入口，承载其下细分业务入口 | 显示为母模块，保留自身查看及真实动作权限 |
| 子页面 / 独立业务 Tab | 业务上隶属母页面，且有单独配置、数据或业务操作职责 | 在母页面组下显示为子模块；已有独立权限模块时继续逐项授权 |
| 普通组件 / 弹窗 / 展示 Tab | 仅呈现所属页面数据，或是其操作表单、筛选和视图切换 | 共用所属页面权限，不创建虚假模块 |
| 独立页面 | 真实业务入口，未归属于其他母页面 | 单独展示其模块及真实权限 |

- 母子关系按实际业务归属和页面入口确定，不仅凭目录、URL 前缀或是否拥有独立路由判断。角色页面权限复用 `RolePermissionsPage.vue` 的统一分组配置及卡片；子页面归入所属母页面，不在“独立页面”中重复展示。
- 有独立业务职责及权限模块的子页面，仍保留自己的查看、动作、路由及后端鉴权。母子分组仅表达业务归属，开启母页面不会自动授予子页面权限，修改子页面开关也不会联动母页面或同组其他页面。
- 配件管理是母页面，配件设置（`/accessories/catalog`，`accessories_accessorycatalogview`）是其子页面，单独控制商品类型、单位和总仓设置的查看、新增、编辑。工资管理下的工资模板、工资计算等沿用同一分组方式。
- 普通弹窗、局部组件及纯展示/筛选 Tab 共用所属页面模块；具有独立业务职责的 Tab 按下列规则登记。字段权限中的“字段分组”描述字段组织，不据此自动创建页面权限模块。综合查询在同一母模块下显式展示“手机模式 / 商品模式”，以既有 JSON 子范围独立保存商品字段，不新增动作模块或放宽已有授权；配置、兼容和接口边界见[字段权限指南](field-permission-guide.md#综合查询的手机与商品字段)。

### 页面权限的展示顺序

- 母页面和独立页面跟随菜单管理中的导航顺序；子页面紧随所属母页面，同组内按菜单顺序排列。`GROUP_CONFIG` 只声明业务归属，不另行维护页面排序。
- `GET /permissions/roles/:id/permissions` 从完整有效菜单读取层级和 `sort_order`，复用公共 `sortModulesByMenu`（内部使用 `buildHierarchicalMenu`）按层级遍历后返回已排序的模块数组；字段模块接口 `/permissions/module-mappings` 使用同一排序入口；同父级、同序号按菜单 ID 稳定排列。前端保持该数组的相对顺序进行母子分组。
- 以菜单 `module_key` 关联权限模块，缺少 Key 时按 `module_id` 解析；同模块重复绑定菜单时采用第一次出现的位置。不按名称或 URL 猜测关联。
- 排序不按查看人或目标角色的可见菜单裁剪模块。菜单隐藏、未授权及未配置有效菜单的权限模块仍可配置；无导航位置的模块保持原分类和名称顺序，排在有导航位置的页面之后；已归组的子页面仍紧随母页面。
- 菜单调序后，下次读取角色页面权限即使用新顺序；排序本身不修改权限、菜单可见性或角色绑定，也不增加前端菜单请求。

### 页面权限按钮

母页面、子页面和独立页面的菜单与动作权限使用公共小号 `el-button`，保留小图标和文字，不再显示图标色块及右侧滑动开关。关闭使用 `tf-button--neutral` 中性灰，开启使用 `tf-button--permission` 紫色；点击整个按钮切换，尺寸、颜色、悬停、聚焦及禁用外观由公共按钮入口负责，页面仅管理分组与换行布局。`aria-pressed` 表达实际授权状态，提示文字说明开启或关闭；图标只作装饰。保存期间原生禁用按钮，保留键盘 Enter/空格操作及原模块键、菜单/业务权限独立保存的边界。正式交互回归与分组共用 `frontend/tests/permission-page-groups.spec.ts`。

### 新增或调整母子页面的登记步骤

1. 核对真实入口、路由、业务职责、权限模块及调用接口。不能以“同一目录就是子页面”或“独立 URL 就是独立业务归属”代替业务判定。
2. 页面模块和真实动作登记到唯一能力清单；角色页面权限的业务分组统一维护在 `frontend/src/views/permissions/page/RolePermissionsPage.vue` 的 `GROUP_CONFIG`，登记母模块键和子模块键，并核对同前缀模块是否确实属于该组。不得另建第二套页面分组配置。
3. 仅调整归属时保持原模块键、角色绑定和接口权限不变，不删除或重建角色权限；前端入口、路由、页面及后端守卫仍检查子页面的原权限。子页面菜单开关与业务权限继续分别处理。
4. 核对字段权限。字段分组不等于页面模块，不得为了界面归组复制字段定义或扩大可见范围。
5. 更新页面台账，并通过实际组件交互验证：子页面只出现一次、归属正确、开关按原模块键保存、母页面权限不代替子页面权限；同时核对普通独立页面以及缺少母模块时的入口保留。

母子分组及排序的正式行为回归为 `frontend/tests/permission-page-groups.spec.ts`；菜单查询、层级调序及授权保留见 `backend/test/role-permissions-controller.check.js`，路由拒绝边界见 `frontend/tests/route-permissions.spec.ts`。运行 `npm --prefix frontend run test:unit -- tests/permission-page-groups.spec.ts tests/route-permissions.spec.ts`、类型检查、定向 ESLint 及 `npm --prefix frontend run check:permissions`；后端执行 `cd backend && ENV_FILE=test/missing-unit-env RUN_DB_TESTS=false node --test test/role-permissions-controller.check.js test/user-menu-controller.check.js test/menu-module-linker.check.js`，仅使用隔离数据；文档变化运行 `npm run check:docs`。权限静态审计核对能力与查看边界，不能代替分组交互或浏览器视觉验收。

### 查看权限边界

- 每个受登录保护的叶子路由必须在 `ROUTE_PERMISSION_MAP` 或 `H5_ROUTE_PERMISSION_MAP` 中配置精确的 `view`，不得依赖父路径前缀兜底。
- 受保护页面必须使用统一 `PermissionGate`；只有路由按钮隐藏而页面组件仍加载数据，不算完整的查看权限控制。
- 路由权限加载失败、权限为空或检查过程异常时必须拒绝访问，不得失败后放行。
- 主页面 `view` 只控制页面外壳。具有独立模块的子 Tab 由自己的 `view` 控制：有权限才显示，无权限时隐藏，手动输入子路由也必须拒绝访问。
- 没有独立路由文件的业务 Tab 仍必须由模块同步器从共享能力清单注册到数据库，禁止因文件扫描不到而停用或从权限配置列表消失。
- 共享能力清单中的模块即使尚未有数据库记录，也必须在模块管理和角色权限列表加载时自动补注册；不能因为数据库已有其他模块而跳过清单模块。规范与审计模块 `standards_standardsauditview` 仅登记 `view`，但必须可在页面权限列表中被授予和撤销。
- 同一数据的状态筛选、列表/卡片切换等纯展示 Tab 共用主页面 `view`，不得为视觉切换制造无业务意义的权限。
- 独立业务 Tab 在 `embeddedViewPermissions` 登记，并在宿主页面使用对应的 `data-view-permission="module:view"` 标记；缺少登记或标记时审计失败。
- 父容器权限不得作为独立子模块 `view/create/edit/delete` 的兜底，否则关闭子模块权限仍可能访问或操作。

## 审计要求

综合查询的手机/商品模式属于同一查询页面的展示切换。商品模式使用本页独立动作 `query:goods-view`，列表及详情接口同时要求 `query:view` 和 `query:goods-view`；销售和赠送分别使用 `query:goods-sell`、`query:goods-gift`，退货/换货分别沿用 `query:return-to-stock`、`query:exchange`。不另建商品查询CRUD模块，不授予 `accessories:view/create/edit`，也不自动授予普通角色权限。字段可见性复用商品模块，由后端限制搜索字段和响应；交易写入仍按真实销售/赠送/售后动作另行鉴权，不能以查看权限替代。契约见[综合查询商品模式](../backend/accessory-entry.md#综合查询商品模式)。

贴膜使用 `query:view` 和 `query:film` 独立授权指定客户设备的最小服务历史、适配商品候选及免费/收费办理；专用接口复用既有候选服务、字段权限和共同结算事务，不要求 `accessories:view/create/gift`，不开放商品管理、普通商品出库或系统管理。设备客户关联、适配、服务门店范围及库存继续逐项核验，不公开原购买店或采购成本，拒绝伪装为贴膜的新手机销售；办理人固定当前账号。手机详情入口已接入，服务撤销尚未接入，普通角色不自动获权。契约见[贴膜服务](../backend/accessory-entry.md#权限与最小历史)。

`check:permissions` 会检查：

- 默认权限是否严格为 `view`；
- 动作定义、中文名称、模块中文元数据、顺序、重复项和扫描别名是否合法；
- 前后端是否读取同一份能力清单；
- 受保护路由扫描结果是否全部登记；
- 每个受保护叶子路由是否有精确 `view` 映射并接入统一 `PermissionGate`；
- 每个模块是否存在后端统一查看映射（本人模块允许 `view:own`，不要求映射为团队查看）；
- 独立业务 Tab 是否已登记并使用自己的 `view` 标记；
- 共享清单中的嵌入式模块是否全部进入数据库模块同步流程；
- 前端模块配置是否重新硬编码权限数组；
- 页面使用的 `canCreate`、`canManage`、`canSync` 等能力是否已在对应模块登记；
- 同一页面引用多个业务模块时，完整权限名调用继续作为对应模块的真实动作证据；不依赖“页面仅有一个权限模块”的推断；
- `canUpdate` 是否继续映射到 `edit`，避免产生虚假的 `update` 权限；
- 公开页面和扫描排除页面是否仍真实存在。

该检查已接入 `check:standards`，并由 `build:release` 和 `check:release` 强制执行；日常构建与启动不运行全量审计。审计失败必须按错误提示补齐真实实现或移除虚假权限，不允许通过新增例外跳过。

## 示例

价目表存在真实同步按钮和同步接口：

```json
"price_list_pricelistview": ["view", "create", "edit", "delete", "export", "import", "sync"]
```

前端和后端必须使用同一个 `sync`：

```ts
const { canSync } = usePagePermissions('price-list')
```

```js
router.post('/sync/trigger', unifiedAuth, requirePermission('price-list:sync'), handler)
```

租赁页面没有独立“管理”操作时，只登记其实际能力，不得追加 `manage`：

```json
"rentals_rentalsview": ["view", "create", "edit", "edit-history"]
```
