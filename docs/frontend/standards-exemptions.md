# 前端规范豁免登记

本文档是前端统一规范的集中豁免台账。它只记录已经确认、范围明确且有公共实现边界的例外，不替代任何规范正文，也不允许页面借此绕开统一组件和审计。

## 登记规则

每条豁免必须同时写明：

- 唯一编号和状态：使用 `EX-UI-001` 这类编号，状态只能是“有效”“待复核”或“已移除”。
- 被豁免的规范和具体规则：必须链接到权威规范正文，不能写成笼统的“样式特殊”。
- 精确范围：写明组件、文件、选择器、字段或业务场景；禁止使用“全站”“所有弹窗”等无限范围。
- 允许内容和禁止内容：明确例外可以改变什么，以及仍然必须遵守什么。
- 公共实现和审计：写明代码入口、验证命令和人工验证重点。
- 复核和移除条件：说明什么时候应迁回统一规则或删除登记。

豁免优先登记在公共组件边界，不登记页面私有样式。新增豁免必须先确认无法通过公共令牌、公共组件或业务布局解决；不得为了让审计通过而修改基线、扩大白名单或登记整页目录。豁免只放宽明确列出的规则，未列出的规则仍然强制执行。

## 新增豁免模板

复制以下结构新增登记，先补充文档和公共边界，再修改代码：

```text
编号：EX-<分类>-<序号>
状态：有效 / 待复核 / 已移除
适用范围：组件、文件、选择器或业务场景
被豁免规则：权威规范和具体条目
原因：为什么公共规则无法直接适用
允许内容：例外允许改变的属性或行为
仍必须遵守：未被豁免的公共规则
公共实现/审计：代码入口、审计命令和人工验证
移除条件：恢复统一规则的条件
最后复核：YYYY-MM-DD
```

## 审核要求

- 页面新增私有视觉覆盖不能引用本台账作为自动许可；必须先判断是否应扩展公共组件。
- 豁免变更必须同时更新本台账、对应权威规范、公共实现和相关审计；只改其中一处不算完成。
- 状态为“待复核”的豁免不得用于新增功能；状态为“已移除”的条目只能保留历史说明，不得继续引用。
- 文档链接和规范覆盖检查统一执行：

```bash
npm run check:docs
npm --prefix frontend run check:coverage
```
