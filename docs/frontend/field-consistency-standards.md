# 字段一致性规范

字段名是前后端、数据库和权限审计之间的契约。一个业务字段只能保留一个规范名称；新增、编辑、删除和查询接口必须使用同一套规范名称。规范请求、响应、表单、列表、权限和统计字段统一使用 `snake_case`，不能在同一业务模块中混用驼峰和下划线命名。

在数据库物理列尚未完成迁移的模块中，旧列名可以暂时只存在于后端边界映射和历史数据迁移代码中，不能出现在新的前端请求或业务计算逻辑中。物理迁移完成后再删除兼容映射。无法安全映射的历史数据必须保留并记录审计结果，不得静默覆盖或删除。

规范字段登记在 `config/field-contracts.json`，前端启动和构建前通过 `check:fields` 审计后端 CRUD 入口与前端 API 类型。新增字段或改名时必须先更新契约、迁移、进度文档和测试，再修改页面。数据库物理列在全站统一完成前不得迁移或删除；模块状态与数据库物理字段映射见 [字段统一迁移进度](../database/field-consistency-progress.md)。

每个契约必须同时登记审计源文件。只新增契约名称但未把实际路由、控制器、服务、repository、前端 API 或 payload 构建器纳入审计，视为未登记。新增业务模块时，`check:fields` 必须覆盖该模块真实入口，且进度文档应区分“契约已登记”“API 已统一”“数据库已迁移”，不能用契约登记代替迁移完成状态。

响应字段同样属于契约。后端可以在 repository 层读取旧物理列，但 service/controller 返回给前端时必须转换为登记的规范分组和字段；前端兼容旧响应只能存在于边界归一化函数中，不能继续扩散到业务计算和新请求。`check:fields` 会同时校验 canonical/response 字段命名格式，旧字段必须登记在兼容清单和边界文件中。
