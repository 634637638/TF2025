本目录保存兼容接口逐批删除前的恢复依据、机器可读清单和批次验收记录。这里不复制运行时 JavaScript 源码；精确源码通过删除前 Git 基线提交和标签恢复，避免归档副本与正式代码产生第二套实现。

## 存放内容

- [机器可读接口清单](route-retirement-manifest.json)：记录 28 个 `migration_id`、10 个 `compatibility_id`、请求路径、权限、替代接口、源码位置、批次和当前状态。
- [源码基线与恢复说明](SOURCE_BASELINE.md)：记录当前分支、HEAD、未提交边界、删除前标签规则和回滚步骤。
- [第一批：库存 410 接口](batch-01-inventory-410.md)：7 个已经返回 `410 Gone` 的库存占位入口。
- [第二批：明确标准替代接口](batch-02-canonical-replacements.md)：5 个已有明确规范入口的旧路由。
- [第三批：兼容适配接口](batch-03-compatibility-adapters.md)：10 个仍承担权限或响应转换的兼容入口。
- [第四批：商城媒体旧接口](batch-04-shop-media.md)：6 个仍需核实 ID、权限和载荷映射的媒体入口。

## 使用规则

1. 当前状态只在兼容接口台账和全局技术债务 T6 中维护；本目录是删除证据和恢复记录，不建立第二份当前待办。
2. 每批删除前必须先提交相关源码并创建 `compat-routes-before-<batch>-YYYYMMDD` 标签；工作区存在未提交相关修改时禁止删除。
3. 每删除一个接口，同步填写删除 commit、部署版本、观察时间、访问次数、受影响页面和回滚结果。
4. 出现旧路径访问或页面错误时，先按 `migration_id`、request ID、用户 ID 和 User-Agent 定位，再回滚对应删除提交；不得从归档复制代码形成长期并行实现。
5. 日志不得记录 Token、Cookie、请求体、搜索关键词或其他敏感数据。
