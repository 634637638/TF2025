# 文档编写与维护规范

本文档规定 TF2025 文档的目录职责、事实标准和维护方式。文档总入口为 [docs/00-INDEX.md](../00-INDEX.md)，新文档可使用[统一模板](../TEMPLATE.md)。

## 目录职责

| 目录 | 放置内容 |
| --- | --- |
| `docs/frontend/` | 前端强制规范正文；以 `standards-manifest.json` 登记为准 |
| `docs/guides/` | 跨模块开发、调试和维护指南 |
| `docs/permissions/` | 权限模型和权限专项说明 |
| `docs/business/` | 已核实的业务规则 |
| `docs/backend/`、`docs/database/` | 后端实现、数据库结构和数据契约 |
| `docs/deployment/` | 当前部署操作说明 |
| `docs/development/`、`docs/performance/` | 有日期的进展、验证或分析记录；需标记适用时间和限制 |
| `docs/archive/` | 已弃用但仍有查阅价值的内容 |

`docs/frontend/` 是强制前端规范的唯一正文目录。同一规范不得在 `docs/standards/`、`docs/components/` 或 `docs/guides/` 再复制一份；旧路径需要兼容时，只保留简短迁移说明并链接权威正文。

## 文档结构

根目录 `AGENTS.md` 和 `CLAUDE.md` 是工具指令入口，属于正文存放在 `docs/` 规则的明确例外。入口只维护执行流程与导航；业务和 UI 规范不重复复制。专项规范负责其领域，跨模块指南及日期报告不能覆盖专项正文。

每份文档应包含：

1. 唯一、具体的一级标题。
2. 开头简述适用对象或用途。
3. 按任务组织的章节；操作文档明确前提、步骤和验证方式。
4. 相关文档的相对链接。

只有内容会随代码或部署状态变化的文档才标注“最后核实日期”。日期表示实际核对日期，不是创建日期；没有复核证据时，不得写“当前”“最新”“已验证”。

不强制添加版本号、维护者、目录、更新日志或状态 emoji。只有确实需要追踪版本或变更的文档才保留这些内容。

## 事实与示例

- 区分已实现事实、建议和待验证事项；不得把规划、估算或推断写成已完成结果。
- 性能数字、成本收益、线上状态和数据库数据必须有可复现的测量方法、日期及范围；没有证据就删除数字或明确标为假设。
- 命令、端口、文件路径、API、组件和导出名必须与仓库当前实现一致。部署文档不能把本机假设写成线上事实。
- 示例凭证、真实密钥、个人数据及可复用的访问令牌不得放入文档。
- 已被代码或配置取代的操作步骤应删除，不以“历史说明”继续放在当前操作指南中。

可直接使用的 TypeScript/Vue 完整示例用代码围栏 `ts check` 或 `vue check` 标记，交由 `npm run check:docs` 使用项目编译器检查导出、参数和类型。片段、反例、伪代码须说明边界，不加 `check` 标记。核心 API、类型和页面模板必须保留已标记示例，不能删除标记绕过失败。

检查只编译示例，不执行请求或数据库操作；未标记的历史片段不属于编译覆盖范围。示例通过不代表接口在线、业务正确或视觉验收通过。

修改文档检查工具时另运行 `npm run test:docs`，验证真实编译的正例、类型/导出/模板错误的负例及临时目录清理。工具自身的负例测试不在每次启动时重复运行。

## 行为变更与文档同步

代码完成不等于任务闭环。发生以下变化时，必须在同一变更中更新对应权威文档，并在交付说明中列出更新位置：

| 变化 | 必须同步的内容 |
| --- | --- |
| API、请求/响应字段、错误码或公开契约 | API/业务正文、类型或字段契约、调用示例和相关测试说明 |
| 权限动作、角色边界、数据范围或字段脱敏 | 权限正文、能力清单、前后端审计配置和拒绝场景 |
| 环境变量、密钥、缓存、数据库结构、迁移或部署方式 | 安全/后端/数据库/部署操作文档、回滚步骤和验证命令 |
| 页面、路由、Tab、弹窗、公共组件或响应式范围 | 前端专项规范、页面与功能单元台账、路由/菜单/权限说明和适用审计 |
| 测试数量、构建结果、线上状态或验收结论 | 对应日期记录中的新核实章节，准确区分通过、失败、跳过和未执行 |
| 文件路径、命令、导出名或公共实现入口 | 所有仍作为当前入口的正文、索引、manifest 和入站链接 |

纯内部重构、拼写修正或不改变外部行为的局部修复不要求新建报告；但如果现有文档引用了被改动的路径、命令、名称或事实，仍须同步修正。没有新增文档需求时优先更新现有权威正文，禁止为同一主题建立第二套规范。判断无需更新文档时，交付说明必须写明理由。

## 文档生命周期与唯一待办

文档必须按用途区分生命周期，禁止同一批问题同时存在于多份“当前待办”中：

| 类型 | 唯一用途 | 完成后的处理 |
| --- | --- | --- |
| 当前任务台账 | `docs/development/TECHNICAL_DEBT_PROGRESS.md` 是唯一当前待完善入口 | 完成项移入该文档的“已关闭”，保留日期和验证证据 |
| 专项契约或完成记录 | 保存仍有效的运行时边界、架构职责和可复现验证 | 标明“已闭环”或“持续维护”，不得另建当前待办 |
| 历史审计快照 | 保存某一日期的发现、测量和当时结论 | 保留原始事实，补充闭环映射并链接唯一当前任务台账 |
| 归档资料 | 保存已被替代但仍有追溯价值的计划或总结 | 移入 `docs/archive/`，注明替代入口，不再参与当前决策 |
| 临时检查产物 | 一次性扫描日志、构建输出、临时截图和中间 diff | 验证完成后删除，不进入正式索引 |

分析或审计报告中的问题处理完成后，必须逐项映射为“已关闭”或迁入全局技术债务台账。旧报告不得继续使用未限定时间的“当前待完善”“剩余治理顺序”“持续技术债务”等标题；需要保留原文时改为“当时状态”并在开头声明当前入口。没有独立证据、完全重复权威文档或事实来源无法确认的报告直接删除，不用归档制造噪声。

归档前必须更新所属索引和全部入站链接。包含两份或以上专题资料的归档子目录必须提供 `INDEX.md`；归档正文必须包含“文档类型：归档资料”和“替代入口”。

## 历史快照

带日期的审计、进展和验证记录必须在开头明确标识，避免被自动化工具或 AI 当成当前规范：

```markdown
> 文档类型：历史审计快照
> 核实日期：YYYY-MM-DD
> 当前状态：请以对应专项规范、当前源码和最新自动检查结果为准
```

- 历史数字和当时结论可以保留，但必须放在明确的日期或“当时状态”章节中，不能与文档开头的当前结论互相矛盾。
- 后续复核应追加带日期的新结论或链接到新的权威记录；不得无证据地把旧结果改写成当前通过。
- 历史快照不得定义新的强制规则。仍然有效的规则必须迁入对应专项正文，并从快照链接过去。
- 当前操作指南不使用“历史快照”标识；其中失效的步骤应直接更新或删除。
- 除 `TECHNICAL_DEBT_PROGRESS.md` 外，开发记录不得建立第二份当前待完善清单；历史报告中的未完成项必须链接到该台账中的任务 ID。

## 链接与索引

- 仓库内 Markdown 文件使用相对路径链接；路径大小写必须与文件名一致。
- 源码位置使用仓库根目录相对的行内代码路径，例如 `frontend/src/components/Example.vue`，不要伪装成相对文档链接。
- 每个包含两份或以上专题文档的目录必须有一个 `INDEX.md` 作为导航；单文件目录可由上级索引直接导航。新增、删除或移动文档时同步更新索引和入站链接。
- 索引只做导航和简短说明，不复制被索引文档的大段正文。
- 已移除的内容若仍有价值，移入 `archive/` 并注明替代文档；不再有参考价值或事实不可靠的内容直接删除。
- 文档变更后运行 `npm run check:docs`，检查 `docs/` 及根指令入口的本地链接、从总索引可达性、已标记示例的类型编译，以及已登记的权威入口、旧数据库测试命令、日志示例、生产密钥模板和基础设施地址冲突。该检查不证明所有历史示例、链接锚点、业务运行或视觉正确。

## 前端规范变更流程

新增或修改强制前端规范时，按 [规范审计接入指南](../frontend/standards-audit-guide.md) 更新规范正文、公共实现、自动审计和 `standards-manifest.json`。仅修改文档而没有同步实现或审计，不构成已落实的强制规范。
