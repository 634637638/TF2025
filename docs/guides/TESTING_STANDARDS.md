# 全局测试与清理规范

本文规定 TF2025 前端、后端、审计工具、数据库回归和临时验证的统一测试边界。目标是保留可重复执行的质量资产，同时在交付前清理一次性脚本、临时数据、调试入口和无用产物。

## 适用范围与权威边界

- 本文负责跨模块测试分类、存放、保留、清理和结果报告。
- 后端真实数据库测试的连接授权、独立测试库、样本和回读要求以[后端数据库回归测试](../backend/database-testing.md)为准。
- 前端页面、组件和公共规范仍按[前端规范索引](../frontend/INDEX.md)选择专项审计；本文不复制各专项的断言细节。
- 测试不能替代生产部署、浏览器、真机或第三方服务验收。每类验证分别报告，不能相互冒充。

## 测试资产分类

不能仅凭文件名包含 `test`、脚本已经运行过或当前功能暂时通过就删除文件。先按用途分类：

| 类型 | 常见位置或示例 | 完成后处理 |
| --- | --- | --- |
| 正式单元、组件、契约、集成和回归测试 | `backend/test/**/*.check.js`、`frontend/tests/**/*.spec.ts`、`scripts/test/*.check.mjs` | 必须保留并随代码维护 |
| 安全漏洞防回退测试 | 注入、权限拒绝、事务竞态、密钥、上传和日志脱敏测试 | 必须保留；不能在修复通过后删除 |
| 规范审计和质量门禁 | `frontend/scripts/check-*.mjs`、根目录检查脚本及其测试 | 必须保留；修改门禁时保留正例和负例测试 |
| 测试公共资源 | fixture、mock、测试环境解析器、事务回滚和样本清理 helper | 有正式测试依赖时必须保留 |
| 数据库迁移、修复、回填、轮换和回滚脚本 | `backend/scripts/migrate-*`、`repair:*`、`rotate:*` 及 `package.json` 命令入口 | 属于运维和灾备资产，不作为临时测试脚本删除 |
| 临时验证脚本或一次性探针 | 为单次排查临时创建、未接入正式测试入口的脚本 | 验证后删除，或整理成正式测试后移入规范目录 |
| 临时页面、路由、接口和调试开关 | 只为人工验证创建的入口 | 验证后删除，并检查路由、菜单、权限和引用无残留 |
| 临时测试数据和文件 | 随机客户、设备、订单、上传文件、缓存键和测试日志 | 测试结束清理并回读确认无残留 |
| 生成产物 | 临时截图、抓包、覆盖率、构建目录、导出文件和本地日志 | 非项目正式资产时删除或保持在忽略提交目录 |

正式测试失败时必须修复实现、测试环境或已经确认变化的业务契约。禁止通过删除测试文件、删除断言、增加无依据跳过、扩大白名单、降低阈值或重建债务基线让门禁变绿。

## 正式测试存放与命名

- 后端正式测试放在 `backend/test/`，使用现有 `*.check.js` 命名；共享资源放在 `backend/test/helpers/`。
- 前端正式行为测试放在 `frontend/tests/`，沿用 `*.spec.ts` 和现有 Vitest 配置。
- 根级工具测试放在 `scripts/test/`；前端审计器测试可与对应 `frontend/scripts/check-*.mjs` 相邻，保持现有命令入口。
- 正式测试必须接入现有 `package.json` 测试或审计命令，或在对应专项文档中给出明确入口。孤立且无人执行的测试文件不算闭环。
- 一次性排查优先使用已有命令和只读查询。确需创建临时文件时，不得混入正式测试目录伪装成回归测试；交付前删除或完成正式化。

## 编写要求

- 优先断言业务输入输出、错误码、权限拒绝、字段脱敏、状态流转、事务、并发、幂等和清理结果。
- 源码字符串或结构审计只用于必须固定的架构边界，例如路由必须经过鉴权或页面必须复用公共入口；不能锁定局部变量名、代码排版、泛型写法或无关实现细节。
- 修复可复现缺陷或安全问题时，应增加能够在修复前失败、修复后通过的正式回归测试。测试名称应说明行为，不使用模糊的 `test1`、`temp` 或 `final-test`。
- 时间相关测试使用项目统一北京时间边界或可控时钟，不依赖运行机器的本地时区和当前日期。
- 外部支付、短信、地图、扫码和第三方接口默认使用 mock、sandbox 或明确的测试环境；未经授权不得向真实客户、商户或外部人员发送请求、消息或付款。
- 测试账号、数据库密码、密钥、Token、Cookie 和真实个人数据不得写入源码、fixture、快照、文档或命令参数。只从当前授权环境加载，日志中必须脱敏。
- 测试必须可重复运行，不能依赖前一次执行残留；并发用例使用唯一标记，不能共享会互相覆盖的固定业务记录。

## 数据与资源清理

- 测试只清理本轮创建且能够准确识别的资源。不得使用无条件 `DELETE`、`TRUNCATE`、清空上传目录、刷新整库缓存或重置自增值作为测试收尾。
- 优先使用事务回滚；需要提交后再查询的独立测试库样本，必须记录本轮主键或唯一标记，并按外键逆序清理。
- 文件、连接池、定时器、事件监听器、临时服务器和 mock 必须在成功、失败和断言异常路径中释放。清理失败必须使测试失败，不能只记录日志后继续报告成功。
- 并发任务必须等待全部任务进入清理阶段后再汇总结果，不能因第一个失败就遗留其他仍在运行的连接或写入。
- 测试进程被强制终止、数据库断连或清理回读不一致时，停止复用该测试环境，先检查残留范围；不得直接重复运行或声称已经通过。
- 浏览器和真机测试产生的截图、视频、下载、上传和本地存储数据应在任务结束后清理；作为正式回归证据保留时，放入约定的证据位置并移除敏感信息。

## 删除测试或脚本前的检查

删除任何测试、helper、审计器、迁移或修复脚本前，必须检查：

1. `package.json`、CI、启动/构建命令是否引用。
2. 源码、测试、动态加载、路由扫描和脚本入口是否引用。
3. 当前规范、迁移说明、部署文档和回滚流程是否依赖。
4. 删除后是否仍有等价覆盖；功能删除、测试合并或契约替换需要指出替代测试。
5. 数据库脚本是否承担灾备重放、回滚、审计或历史结构升级，即使只执行一次也不能据此删除。

正式测试只有在对应功能已删除、测试被等价合并或契约明确替换时才可删除。删除必须与代码、命令入口、文档和测试数量记录在同一变更中更新；不能为了消除失败或减少维护量直接删除。

## 运行与结果报告

- 根据[任务检查矩阵](CODE_REVIEW_STANDARDS.md#任务检查矩阵)执行本次改动适用的最小测试集合；发布验收执行完整发布门禁。
- 报告必须分别列出总数、通过、失败、跳过和未执行原因。重复包含在总套件中的专项测试不能再次累加。
- 数据库测试必须说明是否实际建立连接、使用独立测试库还是明确授权的业务模式，以及清理回读结果。
- 浏览器、真机、摄像头、上传、支付和第三方联调没有实际执行时，应标为“未验证”或“明确延期”，不能用单元测试、设备仿真或源码审计代替。
- 测试结束后检查工作区，确认没有临时脚本、测试数据、调试代码、敏感输出或无用生成产物；正式新增测试、fixture 和必要脚本应保留并纳入提交范围。

## 交付检查清单

- [ ] 缺陷和安全修复已增加必要的正式回归测试。
- [ ] 正式测试位于规范目录并接入现有执行入口。
- [ ] 没有通过删除断言、跳过用例或降低门禁掩盖失败。
- [ ] 临时脚本、页面、路由、数据、上传、日志和调试输出已清理。
- [ ] 迁移、修复、轮换、回滚和审计脚本未被误删。
- [ ] 连接、定时器、监听器、临时服务和 mock 已释放。
- [ ] 测试结果准确列出通过、失败、跳过和未执行范围。
- [ ] 行为或测试状态变化已按[文档维护规范](DOCUMENTATION_STANDARDS.md)同步相关文档。
