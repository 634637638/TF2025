## 防回退规则

1. 机器清单中 `status !== "removed"` 的条目必须与当前路由代码中的迁移 ID、兼容 ID 一致。
2. `status = "removed"` 的历史 ID 不得重新出现在路由代码中。
3. 本站前端不得重新调用 28 个旧路径；规范接口与正式商城媒体删除接口必须继续存在。
4. 禁止恢复已删除的兼容/弃用中间件、日志审计脚本或旧路由契约测试。
5. 如部署后发现真实兼容问题，先记录页面、请求路径、状态码、request ID、用户范围和时间，再决定修正规范调用或按标签恢复单个接口；不得整批恢复。

自动保护由 `backend/test/retired-route-removal-contract.check.js` 和文档冲突检查共同提供。

## 部署后观察

- 检查旧路径 404、前端错误上报、反向代理访问来源和已知外部集成方反馈。
- 核对操作员、考勤、工资、分析、基础资料和商城媒体页面使用规范接口且权限范围未扩大。
- 外部调用证据不足时保持 T6 为“代码删除完成，待部署观察”，但不恢复运行时兼容层。
- 若需要回滚，优先回滚单个删除提交；当前未提交阶段使用删除前标签恢复最小范围。
