# 后端数据库回归测试

本文说明 `backend/test/database-regression.check.js` 的运行条件、样本与清理边界。普通契约测试与真实数据库回归分别报告；跳过不代表通过。默认使用独立测试库；业务库仅在本次任务明确授权、已完成备份且准确指定目标后启用显式模式。

最后核实日期：2026-11-04。文中的 330 项完整后端测试和 21 项安全测试是该次代码版本的实测数量，新增用例后以实际汇总为准。

## 选择运行范围

以下命令均在仓库根目录执行，配置要求见后文。

| 目的 | 入口 | 数据库与验收边界 |
| --- | --- | --- |
| 普通后端检查 | `RUN_DB_TESTS=false npm --prefix backend test` | 14 项数据库回归跳过，不能据此确认数据库功能通过 |
| 测试机制单元测试 | `node --test backend/test/database-test-safety.check.js` | 使用替身验证授权、事务及清理，不连接真实数据库 |
| 仅真实数据库回归 | `npm --prefix backend run test:db` | 默认独立测试库，执行 14 项；业务模式必须另带下文的完整授权参数 |
| 完整后端与真实数据库回归 | `npm --prefix backend run test:db -- --all` | 默认独立测试库；本次云端业务库执行另带了完整授权参数 |

这些范围有重叠：21 项安全/清理单元测试和 14 项数据库回归均包含在本次 330 项完整结果中；单独复跑安全测试不能再次加到总数里。命令运行成功仅证明其覆盖范围，不等于全站人工验收通过。

## 默认入口与目标隔离

默认模式在加载业务配置前校验测试环境，直接设置 `RUN_DB_TESTS=true` 也不能绕过目标检查。

- 必须先准备结构已迁移的独立云端测试库，以及仅有该库权限的测试账号。测试库名必须以 `_test` 结尾，例如 `tf2025_regression_test`；名称检查不能代替实际的库隔离和账号权限。
- 每个并行任务使用各自独立的测试库；不要让多个数据库回归进程共享同一个库。测试使用 `2099-12-31` 作为单号预留日期，并要求该日期没有销售记录。

默认隔离模式仅接受以下专用变量，不使用普通 `DB_*` 凭据作为测试目标：

| 配置 | 要求 |
| --- | --- |
| `TEST_DB_HOST` | 独立测试服务器地址，必填；不硬编码项目主机 |
| `TEST_DB_PORT` | 可选，默认 `3306`，必须为合法端口 |
| `TEST_DB_USER` | 独立测试账号，必填 |
| `TEST_DB_PASSWORD` | 测试账号密码，必填；不写入文档或提交到 Git |
| `TEST_DB_NAME` | 已迁移的独立测试库名，必填，以 `_test` 结尾 |
| `TEST_DB_ENV_FILE` | 可选，显式指定测试环境文件；指定后文件必须存在 |

变量可放在忽略提交的 `backend/.env.test`，也可通过环境变量提供。显式变量优先于测试文件；自定义文件路径按命令当前目录解析，建议使用绝对路径。启动时固定 `NODE_ENV=test`，生产模式会被拒绝，`ENV_FILE` 固定指向专用测试文件，阻止普通 `.env` / `.env.production` 回退。

两种模式连接成功后都会用 `SELECT DATABASE()` 和服务器的 `lower_case_table_names` 核对实际库名；仅在服务器自身折叠大小写时归一化。在创建任何样本前，检查相关表存在且为 InnoDB，并确认供应商付款补列已完成；缺表、缺列或非事务引擎直接失败，不在测试中代替数据库迁移。

## 已备份且明确授权的业务库模式

业务库测试必须已获用户针对本次目标的明确授权。备份不意味着所有操作都可回滚，也不构成以后每次运行的自动授权；日常回归仍优先使用独立库。

在仓库根目录执行以下命令前，将主机、端口和库名替换为本次已确认的真实目标：

```bash
npm --prefix backend run test:db -- --all --live --backup-confirmed \
  --host='已确认的主机' --port=3306 --database='已确认的库名'
```

- 去掉 `--all` 时只执行 14 项数据库回归。业务模式必须带 `--live`、`--backup-confirmed`、`--host`、`--port` 和 `--database`，缺少任一项即停止。
- 入口复用公共配置加载当前环境的 `DB_*`，凭据不进入命令行，不创建专用凭据文件；配置主机、端口、库名必须与授权参数一致，再核对服务器实际库名。仅继承 `DB_TEST_MODE=live` 而未明确传 `--live` 也会被入口拒绝。
- 不更改 `.env`、`NODE_ENV`、服务器全局参数或线上服务。授权参数仅传入本次测试子进程，不持久化到业务配置。
- 样本准备全程只读：选择既有用户角色、基础资料、供应商付款设备与考勤记录，不提交合成用户、角色、门店、客户或销售。缺少样本直接失败。
- 写入前检查 `phones` 和 `invoice_sequences` 无触发器；存在触发器时停止，不能假定回滚可以消除所有副作用。要求单号测试日期无销售记录，且其序列表行已存在；业务模式不自动创建该行。
- 单号使用 `2099-12-31`，8 个事务各生成 20 个号码后全部回滚；不写入销售记录，不占用当前日期单号。库存只在事务内新建随机 `qa_live_` 标记的设备、更新该新增主键并回滚，不更新既有业务设备。
- 测试连接使用 `READ COMMITTED` 减少空日期间隙锁影响，沿用服务器锁等待时长，不修改全局设置或业务连接。此模式不替代独立库中对部署默认隔离级别的验证。
- 库存临时插入即使回滚仍可能消耗自增 ID；不重置 `AUTO_INCREMENT`，不要求业务 ID 连续。
- 结束时必须回读临时设备为零、测试日期销售为零、序列与运行前一致，并输出 `LIVE_DB_TEST_VERIFICATION`；任一不符即失败。不得使用强制进程退出掩盖资源泄漏或跳过回读。

### 结果判定与只读复核

必须同时核对测试进程退出码为 0、最终汇总无失败/取消/跳过，以及结束回读成功。单独看到某条 `ok`、连接池关闭日志或下面的回读标记，都不能代替完整汇总。正常业务模式回读输出示例：

```text
LIVE_DB_TEST_VERIFICATION {"temporaryPhones":0,"sequenceUnchanged":true,"testDateSales":0}
```

需要独立复核时，使用已授权的数据库只读连接执行以下查询；不要在脚本、文档或命令行中填写密码：

```sql
SELECT DATABASE() AS database_name,
       @@lower_case_table_names AS lower_case_table_names;

SELECT COUNT(*) AS temporary_phones
FROM phones
WHERE LEFT(imei, 8) = 'qa_live_'
   OR LEFT(serial_number, 8) = 'qa_live_';

SELECT COUNT(*) AS test_date_sales
FROM sales
WHERE invoice_number LIKE '20991231%XS';

SELECT current_sequence
FROM invoice_sequences
WHERE sequence_date = '20991231' AND type_suffix = 'XS';
```

库名须符合授权目标；前两项计数应为 0，序列必须有且仅有一行并与本轮运行前记录值相等。本轮原值为 0，但后续不能将 0 当作所有环境的固定原值。前缀查询用于补查所有此类临时设备，正式测试自身按本轮随机标记精准核验。

若测试失败、回读不一致或进程未退出，先确认所有并发任务已回滚/释放，再定位原错误码与残留范围；不得直接重复启动、清表、重置序列或覆盖恢复业务库。修复后保留原并发数量与业务断言，重新取得完整退出状态。报告保留失败原因和修复后的结果，不能只截取成功片段。

| 提醒列表 | 实际字段、提醒聚合与规范分页 |

## 隔离库样本与公共资源清理

- 使用 `backend/test/helpers/database-fixtures.js` 创建带随机 `qa_` 标记的合成资料、禁用登录的测试用户、角色关联、门店、库存与考勤，不复制业务用户或客户资料。
- 样本在独立库中事务提交，让真实仓储的连接池查询能读到；不通过一条连接内的 mock 查询替代数据库行为。
- 单号和库存修改统一使用测试资源工具 `withRollbackConnection`：成功、准备失败、事务启动失败及断言失败均尝试回滚，回滚失败则销毁连接，保留原错误和清理错误。
- 并发任务使用 `Promise.allSettled`，等待每条连接完成清理后才汇总失败、关闭连接池。
- 预检池在 `before` 的 `finally` 中关闭，随后各用例和结束回读分别建立并关闭连接池，避免创建新池时覆盖尚未释放的预检连接。并发失败保留每个任务的原错误，并汇总错误码辅助定位。
- 测试结束按本轮记录的主键及外键逆序删除合成样本，清理本轮新增的预留日期序列表行；不清表、不重置自增值、不删除已有序列。样本创建和清理失败都必须使运行失败。
- 进程被强制终止或数据库断连时，不能保证清理完成。此时停止复用该测试库，检查残留标记和失败日志，或重新建立独立测试库后再运行，不能将失败写成成功。

`backend/test/database-test-safety.check.js` 是不连接真实数据库的安全与资源管理测试，共 21 项，覆盖配置拒绝、目标不匹配、准备/启动/断言/回滚失败、连接获取部分失败、样本写入和清理失败，以及业务模式授权、只读样本准备、临时库存回滚与结束回读。单元测试显式传入环境，不能因完整测试继承业务模式而改变断言语义。它验证测试机制，不证明上述 14 项真实数据库回归已经通过。

## 验证记录与交接

修改测试时执行专项单元测试、完整后端测试、定向 ESLint 和 `git diff --check`；文档修改另执行 `npm run check:docs`。结果中分别填写总数、通过、跳过、失败，以及真实数据库连接是否实际建立。

2026-11-04 前一阶段缺少专用测试环境，默认隔离入口已确认会在建立连接前拒绝缺失配置。用户随后确认云端已备份并明确授权直接测试，本轮新增显式业务库入口并实际连接；结果须以本轮完整退出状态、测试汇总和清理回读为准，历史云端结果不能代替本轮验收。独立测试库的合成样本创建与删除路径仍待独立环境实测。

本轮显式业务模式使用上述 `--all --live --backup-confirmed` 入口，并传入当次已授权的主机、端口和库名；实际连接地址不保留在规范正文，也不能作为以后环境的默认值。初跑发现测试会话将锁等待缩短至 15 秒，导致并发用例超时，以及单元测试继承业务模式、预检池未关闭两项测试机制问题。修复后沿用服务器默认 50 秒锁等待，保留 8×20 单号生成及全部断言，完整后端 **330 项通过、0 失败、0 跳过，退出码 0**，约 44.86 秒；单号并发约 30.10 秒。已包含在总数中的 21 项测试安全/清理单元测试也单独复跑通过。

结束回读和另一次独立只读连接均确认：`qa_live_` 临时设备为 0，测试日期销售为 0，既有序列值仍为 0；连接池正常关闭。真实写入仅发生在回滚事务内，本次未改业务单号算法，也未恢复备份、改写既有销售或重置自增值。本结果不等于完整 HTTP、浏览器、真机验收，也不证明独立库合成样本流程已实测。
