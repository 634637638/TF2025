# 备份管理

本文说明 `/backup` 管理页支持的备份类型、文件格式和下载边界。备份数据来自后端运行环境配置的 MySQL 连接。

## 备份类型

| 类型 | 内容 | 文件格式 |
| --- | --- | --- |
| 仅数据库 | 当前 `DB_NAME` 对应数据库的结构与数据 | `sql-YYYYMMDD_HHMMSS.sql` |
| 完整备份 | 数据库、后端代码及 `backend/uploads` 文件 | `backup_YYYYMMDD_HHMMSS.zip` |

创建接口为 `POST /api/backup/create`，请求体 `type` 可取 `database` 或 `full`。为兼容旧客户端，省略 `type` 时按 `full` 处理。两种文件都会进入同一备份目录，并通过备份列表、受控下载、删除、容量统计和旧备份清理管理。

新建数据库备份统一使用 `sql-` 前缀，例如 `sql-20261109_142759.sql`；完整备份继续使用 `backup_` 前缀，例如 `backup_20261110_172204.zip`。已有 `database_YYYYMMDD_HHMMSS.sql` 保留原名，仍可在列表查看、下载、删除及上传云盘，已有云盘任务与断点继续按原文件名匹配。

## 恢复说明

数据库备份是 SQL 导出文件。恢复前应选择目标数据库并确认覆盖影响，再使用 MySQL 客户端导入，例如：

```bash
mysql -h "$DB_HOST" -P "$DB_PORT" -u "$DB_USER" -p "$DB_NAME" < sql-YYYYMMDD_HHMMSS.sql
```

完整 ZIP 包含数据库导出、代码和上传文件快照；后端代码部分会保留 `server.js`、唯一生产入口 `start-production.js` 及 `ecosystem.production.config.js`。它不会自动部署或覆盖运行中的服务。请先在隔离环境检查压缩包内容，再按部署流程恢复。

## 定时生成与本地保留规则

页面“清理旧备份”为手动清理入口，需 `backup:delete`，不要求本地备份达到 5 份；列表非空且未加载或清理时可打开，保留数量可选 1–20 份。打开时默认值不超过“现有份数减一”（至少为 1），提交后按全部本地备份的时间顺序保留最近 N 份，SQL / ZIP 共用该手动数量；数量未超过保留值时不删除。此操作仅清理本地文件，云盘文件保留，与下述自动清理的分类保留规则独立。

在“云盘设置”中配置“定时生成备份”，选择 SQL（仅数据库）或完整 ZIP（数据库、后端代码和上传文件），间隔为 1–720 整数小时，默认 24 小时、默认关闭。现有“自动备份”开关仍负责把 `backups` 内完成的文件上传云盘，两者独立：仅开启定时生成会保留本地文件，同时开启自动上传才会自动发送到所选账户及目录。当前入口仍需先添加云盘账户、选择目标目录后保存。

调度在后端执行，关闭浏览器不影响执行；后端每 60 秒检查到期计划，复用 `BackupService.createBackup` 和既有上传队列，不在浏览器挂定时器。首次启用或改变间隔/类型时从保存时间计算下一次；保存相同规则不顺延时间。成功完成后按完成时间加间隔计算下一次；停机期间不执行，重启后已到期的规则只补做一次，不逐个追补错过的周期。后端忙于上传、备份或被其他进程占用时延后到空闲检查；正在手动生成备份时不并发创建。生成失败或检测到重启中断，持久化脱敏错误并在 5 分钟后重试；半成品不进入上传队列。页面再次打开时展示最近执行结果和下一次时间，显示统一为北京时间；备份文件名也使用北京时间，不依赖服务器时区。

“自动清理本地旧备份”默认关闭，SQL、ZIP 各自默认保留最新 10 份，可分别设置 1–1000 份。开启后后台每 5 分钟检查一次，只清理服务器 `backups` 顶层、符合命名且已完成的 SQL/ZIP，旧 `database_` SQL 一并计数；按文件修改时间从新到旧分别保留，其他规则文件、子目录、临时项、符号链接、空文件和半成品不参与数量计算、不自动删除。清理后本地文件无法恢复，**云盘文件和云端成功记录全部保留**。规则不会修改原手动清理功能的行为。

排队、上传和等待重试的文件始终受保护。自动上传开启时，旧本地文件还须在当前账户、目标版本及文件指纹上存在成功上传记录才能清理；失败、尚未上传或内容变更的文件保留，因此本地实际份数可能暂时超过上限。清理失败展示脱敏提示，5 分钟后再试；SQL、ZIP 的保留数量是两组独立上限，不共用总数量。

规则保存在现有 `backups/.cloud/state.json` 的顶层 `schedule` / `retention` 字段，旧状态缺少这些字段时默认关闭，无需数据库迁移。部署必须保留此目录、原 `CONFIG_ENCRYPTION_KEY`、备份目录写权限，以及现有数据库导出运行条件；后端停止时不执行定时任务。本机进程工作锁同时覆盖生成、上传和清理，支持同机共享状态文件的进程互斥；多服务器各自磁盘不共享计划，不属于当前部署支持范围。

设置响应新增 `schedule`（enabled、intervalHours、type、nextRunAt、lastRunAt、lastStatus、lastError、lastFilename）和 `retention`（enabled、sqlCount、zipCount、lastRunAt、lastDeleted、lastError）。时间字段为 ISO 时间点或 null。保存时可提交 `schedule` 的前三个配置字段和 `retention` 的前三个配置字段，运行状态字段由服务器维护；省略某组保留原规则。设置接口继续要求 `backup:create`，请求包含 `retention` 时额外要求 `backup:delete`；无删除权限的前端隐藏清理区域且不提交该字段，不能仅凭创建权限开启自动删除。

回归：`node --test backend/test/backup-automation.check.js backend/test/cloud-backup.check.js` 以及 `npm --prefix frontend run test:unit -- tests/cloud-backup-settings.spec.ts`。测试使用临时文件、模拟导出和模拟云盘，不创建真实数据库备份、不清理真实备份或云盘数据。

## 阿里云盘自动上传

`/backup` 的“云盘设置”支持多个命名账户。点击“新增账户”，填写账户名称（1–50 个字符，不能重名）和网页登录 `refresh_token`（也接受包含该字段的完整 Token JSON），保存账户后在“储存账户”下拉框选择。编辑账户时 Token 留空保留原授权，填写新 Token 会清空该账户原目录，并在该账户为当前上传账户时暂停自动上传，须重新选择目录并保存设置。新增账户和仅切换预览不会改变后台存储账户或开关。

选中账户后点击“浏览云盘 / 选择目录”，识别该账户的资源库/备份盘。文件浏览支持切换云盘、进入子目录、面包屑返回、分页加载和刷新；点击“使用此目录”选择当前目录（包含根目录），返回设置后单行显示“当前备份目录：资源库/文件夹名称（或备份盘/文件夹名称）”，盘名使用账户实际云盘名称；每次打开设置或切换账户时按已保存的 Drive ID / 文件夹 ID 读取最新目录名称，并同步本地展示名称；云端改名不改变目标 ID、任务版本或自动备份开关，不会重新创建旧名目录。读取失败保留上次名称并提示，仍可浏览云盘重新选择；未保存的新目录选择不会被旧目标名称覆盖。选好目录后保存设置，将所选账户及目录设为上传目标。目录和 Drive ID 由选目录操作内部传递，回收站不能作为备份目录。账户列表及设置接口只回传名称、账户 ID、目录和“已配置”状态，不回传 Token 或设备私钥。设置弹窗将账户、自动备份和目标目录分组展示：桌面账户选择与新增/编辑操作同排，手机改为纵向；备份开关与说明对齐，目录使用斜杠路径展示。设置表单和账户编辑分别使用公共中号及小号弹窗档位，文件浏览沿用宽工作区；移除说明性提示及底部“关闭”按钮，保留标题栏关闭能力；账户编辑及文件操作中锁定必要的关闭和切换入口。

首次打开文件浏览时，若原选云盘根目录为空，会依次检查其他可用云盘，找到有内容的云盘后切换显示，并提示原盘为空、当前显示的云盘名称。此过程只改变浏览位置，实际上传目录仍需点击“使用此目录”并保存设置后才会改变。手动切盘、刷新、子目录及回收站不触发自动切换；所有盘均为空时保留原盘，空状态明确标注当前云盘和目录，读取失败显示错误。

页面提供独立的“云盘管理”入口，可选择任一已保存账户浏览对应文件，不修改授权或自动上传配置。查看云盘和回收站需要 `backup:view`；新建文件夹需要 `backup:create`；文件及文件夹重命名、回收站恢复需要 `backup:edit`；删除（移入回收站）及彻底删除需要 `backup:delete`。新建及重命名复用全局通知：成功提示“文件夹创建成功”或“重命名成功”并关闭输入框、刷新列表；失败只提示一次，保留名称供修正，不把失败刷新为空数据。新建及重命名采用公共表单弹窗，名称为 1–255 个字符，拒绝路径分隔符、控制字符及特殊字符，重名时报错并保留输入，不覆盖云端已有内容。文件重命名须保留所需扩展名；此入口不编辑文件内容。上游新建或重命名成功响应只返回文件 ID 时回读核验名称、类型及目录归属，不因缺少展示字段误报失败，也不重复提交；保存成功后列表刷新失败单独显示读取错误，不改报保存失败。

文件和文件夹均可经统一确认框移入回收站；删除文件夹包含其所有子项。后端禁止修改或删除根目录，禁止删除当前备份目录及其父目录，须先更换备份目录；未上传完成的文件不能管理。后台上传期间，同一账户的浏览、新建文件夹及重命名复用上传客户端，不等待整份备份完成；在途管理请求结束前继续持有工作锁，避免授权轮换、目录名称及任务进度互相覆盖。删除、恢复和彻底删除仍返回 `409`，其他账户连接保持隔离。重命名当前备份目录会同步保存的目录名称，目录 ID 及上传目标不变。

普通文件列表操作显示“打开、编辑、删除”；打开用于文件夹，编辑用于修改名称，删除确认框说明文件会移入回收站。“回收站”展示所选账户和云盘中已删除的文件，逐项按“删除、恢复”顺序显示；“删除”实际彻底删除，确认框明确不可恢复；不展示说明提示。两处删除按钮统一复用公共 `table-action--delete` 语义样式。恢复回读文件确认已正常可用；彻底删除前使用统一确认框说明不可恢复、文件夹包含子项及本地保留，后端仅允许对已在回收站的文件或文件夹执行，不能借此删除正常文件。云端返回异步任务时等待任务成功；失败、仍在处理中或回读未确认时不提示操作成功。云端删除不影响本地文件；通过此入口删除已上传备份或包含历史备份的目录时，同步将受影响的成功任务标记为可手动重传，避免仍显示已上传。恢复仅将本账户中此前已失效（兼容旧版因云端删除而标记失败）、且回读文件大小与任务一致的备份重新标为成功；目录恢复逐份核对，缺失或大小变化的备份不标成功。彻底删除后对应任务标为可重新上传，其他账户同名文件 ID 不受影响。回收站和文件列表只返回名称、ID、类型、大小，不暴露签名下载地址或原始第三方响应。

删除、恢复和彻底删除兼容云端 `204 No Content`，仅这些明确的文件变更操作允许空成功响应，其他接口仍校验 JSON；恢复和彻底删除仍须后续回读核验。重复提交已在回收站的文件返回成功，并修正对应任务的上传状态；其他客户端在预检后先删除时，只有回读确认文件确已在回收站才视为完成，不把任意 `404` 当作成功。重命名已删除或未完成的文件返回 `409`，找不到资源返回 `404`；云盘授权失效返回 `409` 并提示重新连接，不使用站内 `401`，避免误触发站内登录刷新。真实上游服务故障仍保留 `502`，沿用全局安全脱敏。

开启“自动备份”（开关说明为“开启自动备份backups内所有文件。”）后，后端每 60 秒递归扫描 `backend/backups` 内普通文件，后续新增规则生成的其他格式也可自动入队；子目录在所选云端目录下按原层级建立，重传复用已保存的云端子目录及分片会话。扫描不跟随符号链接；排除隐藏文件/目录（包括 `.cloud` 授权状态）、`tmp` / `temp`、完整备份生成中的 `backup_YYYYMMDD_HHMMSS` 工作目录，以及 `.tmp` / `.temp` / `.part` / `.partial` / `.crdownload` / `.lock` / `.swp` / `~` 临时项。空文件不入队。普通新格式文件须连续扫描确认大小和修改时间至少 60 秒不变，再入队；生成器仍应先写临时文件再原子改名，避免长暂停写入被误认为完成。此扫描开关不负责生成备份；定时生成由上节独立规则控制，不监控业务上传目录，也不改变现有完整 ZIP 的内容。关闭自动上传后停止扫描及自动排队任务，列表中的 ZIP 和 SQL 仍可手动上传。

新创建的 ZIP、SQL 分别先写入 `.zip.tmp`、`.sql.tmp`，生成结束后原子改名。数据库导出须同时等待 mysqldump 进程成功和目标写流完成，再发布 SQL 或压缩完整备份。规范命名的备份额外核验 ZIP 尾部中央目录结束记录；SQL 检查本项目完成标记，并兼容旧 mysqldump 的 `-- Dump completed on` 结尾或程序化导出的 `SET FOREIGN_KEY_CHECKS=1;` 结尾。空文件、没有完成标记的 SQL、临时文件不入队，防止上传半成品。任务串行执行，使用流式分片上传，不把整个包读入内存；保存每个分片的进度，上传网络失败先重试分片，仍失败时按退避策略重试整项任务（最多 5 次）。后端重启读取原任务与云端上传会话，继续未完成分片；上传地址按分片刷新，避免长期任务的签名过期。上传成功前校验本地文件未变动及云端返回大小。云盘接口或授权拒绝时显示失败，不把本地压缩成功当作云盘备份成功。

分片 PUT 必须保持签名要求的空 `Content-Type`，不能增加 `application/octet-stream`，也不能让 Axios 自动补充表单类型，否则 OSS 返回 `403 SignatureDoesNotMatch`。分片只携带长度等上传所需头，不附带站内或云盘 API 的认证头；云端提前拒绝时销毁并等待文件流关闭。网络异常、超时、限流和服务暂时故障可以重试；签名错误、权限拒绝、本地文件不可读和服务器时钟偏差直接给出对应提示，不盲目重试。分片响应明确返回 `NoSuchUpload` 时清除失效会话。错误只提取已知 OSS 错误类型或 HTTP 状态，不回传响应原文、签名 URL 或本地路径。

恢复已有会话时先通过 `/v2/file/list_uploaded_parts` 核对当前断点分片；网络重试遇到 `409 PartAlreadyExist` 时也执行相同核对。只有云端分片大小及 ETag 与本地对应字节的 MD5 一致，才推进断点并继续后续分片。云端尚未接收该片时正常上传；无法核对或内容不一致时停止，不把任意 `409` 当成成功，也不重复创建整份备份。

任务状态分为等待、上传、等待重试、成功、失败、文件失效。`invalid` 表示已上传文件后来在云端删除，页面显示“文件失效”和“该文件云端已删除，可重新上传！”，使用警告语义色；实际上传错误仍为 `failed`，显示“上传失败”。共享前端契约唯一维护于 `frontend/src/types/backup.ts`。成功的相同文件和目标不重复上传；同名文件不会覆盖云盘既有备份。排队或上传中的本地备份禁止删除，清理旧备份时跳过；云端成功后仍保留本地文件，本地删除不会同步删除云盘文件。失败可在列表重新提交，保留仍可用的分片会话；云盘明确返回上传会话失效时清除断点，下次手动重传创建新会话。更换账户、授权或目录后，列表显示当前账户及目标的上传状态，旧目标的成功记录不阻止向新目标上传。待上传任务存在时拒绝更换目标或授权；可先关闭自动上传以取消自动任务，手动排队任务须等待完成。云盘删除只同步该账户的任务，避免不同账户的同名 ID 相互影响。

任务读取和后端定时调度会触发后台云端核验，不阻塞列表响应；请求去重且至少间隔 60 秒，每批最多核验 20 条当前账户及目标的成功或失效记录，优先处理最久未核验的记录。页面每 5 秒轮询任务结果，因此外部删除或恢复并非即时显示，批量记录需要轮流核验。按原 Drive ID / 文件 ID 查询，只有明确不存在或已在回收站才标为文件失效；文件恢复且类型、大小与记录一致后自动回到“已上传”并清除失效提示。大小不符显示独立核对提示，缺少有效大小、网络或授权故障、文件处理中均保留原状态。旧版因移入回收站或彻底删除而标记失败的记录兼容为文件失效；失效文件不会由自动扫描重复上传，可手动重新提交。核验迟到响应不得覆盖新账户、目标或已重新排队的任务，授权轮换与任务进度不被旧快照覆盖。

凭据与任务状态保存在 `backend/backups/.cloud/state.json`，目录权限 `0700`、文件 `0600`，写入采用原子替换。状态格式为 version 2，账户分别保存授权和目标，config 仅保存当前账户 ID 与开关，任务携带账户 ID。旧 version 1 单账户状态读取时兼容为“默认网盘”，保留原 revision、授权和分片断点，下次写入采用新格式。每个账户独立缓存客户端及持久化轮换 Token；上传期间仅当前上传账户的浏览复用其客户端，其他账户连接返回忙碌提示，禁止串用授权。非上传期间的云盘操作沿用本机进程锁。Token 和设备私钥复用 `config-secret-crypto.js`、`CONFIG_ENCRYPTION_KEY` 加密；轮换后的 refresh_token 立即加密保存。该状态目录不进入完整 ZIP、不提供静态或下载访问；部署须持久化并允许后端用户写入，禁止手动覆盖运行中的状态文件。配置密钥仍由服务器环境管理，不能将密钥与 ZIP 一起公开。当前持久化队列面向一个后端实例及本机磁盘，使用进程工作锁防止重复上传；多服务器共享队列不在本轮支持范围。

第三方适配器为 `backend/src/services/aliyun-drive-client.js`，使用阿里云盘网页登录 Token 及设备会话协议，独立 Axios 客户端，不携带站内 JWT/CSRF，不转交 Token 给第三方代理；分片只接受阿里云盘/阿里云存储 HTTPS 地址并禁止重定向。账号云盘通过 `https://user.alipan.com/v2/user/get` 识别资源库和备份盘，文件操作仍请求 `https://api.alipan.com`；文件服务的 `/v2/user/get` 只返回旧默认盘，不能用于完整云盘识别。若默认盘为空，可在浏览器的“云盘”选项切换资源库，确认后选择实际备份目录。此网页登录协议属于客户端接口，可能随云盘调整或账号策略变化，不等同开放平台的稳定应用授权；需要真实账号联调确认可用。不能用 PC/App 标称 100GB/500GB 上限推断接口上传上限，实际以云盘接口、容量及账号授权为准。

| 接口 | 权限 | 用途 |
| --- | --- | --- |
| `GET /api/backup/cloud/settings` | `backup:create` | 读取脱敏云盘配置及 schedule / retention 规则与运行状态 |
| `PUT /api/backup/cloud/settings` | `backup:create` | 保存 accountId、目录、上传开关及可选 schedule / retention；含 retention 时另需 backup:delete |
| `GET /api/backup/cloud/accounts` | `backup:view` | 获取脱敏命名账户列表及当前存储账户 ID |
| `POST /api/backup/cloud/accounts` | `backup:create` | 以 name / token 新增账户，不切换上传目标 |
| `PATCH /api/backup/cloud/accounts/:accountId` | `backup:create` | 修改账户名称及授权；Token 留空保留原授权 |
| `POST /api/backup/cloud/connect` | `backup:create` | 按 accountId 识别云盘并刷新目标名称，返回 directory（CloudDirectory 或 null）及 directoryError；只更新展示名称 |
| `GET /api/backup/cloud/drives` | `backup:view` | 按 accountId 识别云盘并刷新该账户目标名称，返回同 connect；不改变储存账户、目标 ID 或开关 |
| `GET /api/backup/cloud/files` | `backup:view` | 按 accountId / driveId / folderId / trash / marker 浏览目录或回收站 |
| `POST /api/backup/cloud/folders` | `backup:create` | 按 accountId / driveId / folderId / name 新建文件夹，拒绝同名 |
| `PATCH /api/backup/cloud/files/:driveId/:fileId` | `backup:edit` | 按 accountId / name 重命名文件或文件夹，拒绝同名 |
| `DELETE /api/backup/cloud/files/:driveId/:fileId` | `backup:delete` | 按查询参数 accountId 将对应账户文件移入回收站，本地文件保留 |
| `POST /api/backup/cloud/trash/:driveId/:fileId/restore` | `backup:edit` | 请求体 accountId，恢复回收站文件或文件夹并核验 |
| `DELETE /api/backup/cloud/trash/:driveId/:fileId` | `backup:delete` | 查询参数 accountId，彻底删除回收站文件或文件夹并核验，本地保留 |
| `POST /api/backup/cloud/test` | `backup:create` | 测试授权和目标目录 |
| `GET /api/backup/cloud/tasks` | `backup:view` | 读取无凭据、无签名 URL 的上传状态 |
| `POST /api/backup/cloud/upload/:filename` | `backup:create` | 提交已有 ZIP / SQL 或重试失败任务 |

自动上传设置意味着将 backups 内符合上述扫描规则的文件发送到所选账户的私人云盘目录。首次配置后，应先关闭自动上传，测试连接并手动上传一份备份核验，再按需开启自动上传。所有接口复用“用户 → 角色 → 权限”链，后端逐接口检查。备份模块 `backup_backupview` 的能力清单新增 `edit`；部署后按[页面权限能力规范](../frontend/permission-capability-standards.md)执行模块同步，再在角色权限界面明确分配。同步仅为启用的管理员角色补齐模块能力，普通角色不会自动获得重命名权限。

行为回归：`node --test backend/test/cloud-backup.check.js backend/test/backup-sql-publish.check.js backend/test/backup-types-contract.check.js backend/test/backup-archive.check.js`，以及 `npm --prefix frontend run test:unit -- tests/cloud-backup-settings.spec.ts tests/cloud-drive-browser.spec.ts tests/backup-cloud-status.spec.ts`。分片回归使用真实 Axios 和本机 HTTP 接收端核对实际请求头、字节范围及长度，并检查错误分类和脱敏。这些自动测试使用临时目录及模拟云盘，不访问真实云盘、不写业务数据库；第三方真实上传和服务器重启验收需另行完成。

## Git 管理页项目压缩包

`/git-management` 的“创建压缩包备份”生成 `.tar.gz` 源码快照，与 `/backup` 的完整 ZIP 是不同用途。快照包括 `frontend/`、`docs/`、根目录 `package.json` 和可用的 lockfile、`shared/`（存在时），以及后端 `src/`、`scripts/`、`package.json`、`package-lock.json`、`database/`、`migrations/`、`.env.example` 和 `src/config/runtime-files.js` 登记的生产启动文件。

快照排除 `node_modules/`、构建产物、日志、上传文件、本地备份、`.git/`、SQLite 文件和真实环境文件（包括 `.env.production`）。它带上部署说明和规范正文，但不携带生产凭据、运行数据或上传资产；恢复时仍需安全配置 `.env.production`、运行 `npm ci`，并按业务备份流程恢复数据库与上传文件。

后端生产启动文件的唯一清单位于 `backend/src/config/runtime-files.js`，同时供完整备份与 Git 管理页压缩包复用。若新增或移除部署必需目录/文件，应同步更新 `backend/src/services/git-archive-backup.service.js`、`backend/test/git-archive-backup-controller.check.js` 与本节，并检查环境文件、日志、上传和生成数据的排除规则。

## 权限与验证

- 创建需要 `backup:create`；查看和下载需要 `backup:view`；删除与清理需要 `backup:delete`。
- 下载仍使用短时下载令牌，文件名必须匹配服务端允许的备份命名格式。
- 后端契约测试：在 `backend` 目录运行 `npm test`。
