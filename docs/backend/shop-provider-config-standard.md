# 商城地图与支付服务配置

## 服务商结构

商城服务使用 `H5_config` 持久化 provider 配置。配置键以服务商命名（如 `map_provider`、`wechat_pay_*`、`alipay_*`），公共配置读取必须使用显式字段白名单。新增服务商时新增独立适配器与配置键，不得把凭据塞入通用公开配置对象。

当前管理页支持腾讯/高德/百度地图服务商选择，以及微信支付、支付宝和其他支付服务商参数。支付方式区只展示启用状态、资料完整性和默认方式；所有支付启停及资料均在“支付接口”模态框分类型维护：二维码与转账、微信商家接口、支付宝商家接口、其他服务商。商城公开配置按启用状态和资料完整度生成可用支付方式，服务端创建订单时再次校验。

二维码和银行转账已经接入订单支付方式闭环：订单保存标准化支付编码 `qr_wechat`、`qr_alipay`、`qr_other`、`bank` 或 `pickup`，订单成功页只展示订单所选方式。微信/支付宝商家接口目前只保存配置，不会进入商城可选方式，必须先完成真实下单、异步回调验签、订单状态幂等更新和主动查单适配器后再开放。

## 密钥要求

- 腾讯、高德、百度地图 Key/AK 都是浏览器公开凭据，商城公开接口只允许返回当前地图运行所需的公开 Key。必须在地图服务商控制台限制允许访问的域名；禁止填写服务端密钥。
- 微信 API v3 Key、微信商户私钥、支付宝应用私钥和其他签名秘密使用 AES-256-GCM 加密后存储。
- 生产后端必须配置独立、稳定的 `CONFIG_ENCRYPTION_KEY`，由安全随机数生成并保存在后端环境文件。运行时禁止回退到 `JWT_SECRET`，也不能使用前端 `VITE_` 变量或提交到仓库。
- 轮换支付配置密钥时，先把旧 current 保存为 `CONFIG_ENCRYPTION_PREVIOUS_KEY` 并设置新 current。应用只使用 current 加密新值，但可用 current/previous 解密；随后运行 `npm --prefix backend run migrate:config-encryption-key` 预览并追加 `-- --apply` 迁移存量密文。迁移脚本逐条回读、条件更新并保留一步回滚备份；不能直接覆盖 current 后重启。
- 管理 API 只回显秘密字段掩码。提交掩码表示保留原值；清空字段才删除已保存密钥。公开接口不得返回任何支付凭据。
- 回调地址须使用 HTTPS，并在服务商后台配置相同地址。回调必须验签、校验金额和订单号，并对重复通知幂等处理。

## 现有支付兼容

微信/支付宝收款二维码、银行信息和线下收款保持现状。接口配置页不自动切换商城支付行为。真实支付渠道只有在 provider 适配器、回调路由、安全审计和沙箱验证完成后才可启用。

## 验证

- 后台配置读取时确认支付秘密只返回掩码。
- 保存后检查数据库值以 `enc:v1:` 开头，且商城公开配置响应不含任何 `wechat_pay_*` 或 `alipay_*` 密钥。
- 轮换后执行配置密文迁移预览应显示 `requiresMigration: 0`；超过回滚观察期后再移除 `CONFIG_ENCRYPTION_PREVIOUS_KEY`。
- 配置读写权限使用统一 `h5-config:view/edit` 权限和字段权限；不能新增绕过认证的管理接口。
- 上线前以服务商沙箱验证成功、失败、重复回调、金额不符和签名错误场景。
